## 0. Одно осознанное отступление от плана v2.2

Всё поведение из v2.2 сохраняется без изъятий. Меняется **одно** решение — где хранятся окна.

| | План v2.2 | План v3 |
|---|---|---|
| Хранение окна | запись в `state.layers` с флагом `isLevelWindow` | **отдельный словарь `state.levelWindows`** (как сейчас в коде) |
| Ключ | стабильный `lvlwin-UUID` | **стабильный `lvlwin-UUID`** (как в v2.2) |
| Undo / экспорт | достаются даром, потому что окно — слой | **4 явные строки**: словарь добавляется в снапшот, в `UNDO`, в `REDO`, в экспорт |
| Изоляция от логики слоёв | 13 отрицательных инвариантов, снимаемых фильтром `getPlainLayers` | **не нужна вовсе**: машинерия слоёв физически не видит окон |

**Почему так проще и надёжнее.** Единственный аргумент v2.2 за «окно = слой» — бесплатные
Undo и экспорт. Плата за эту бесплатность — 13 мест, где окно нужно **исключить** из логики
слоёв, причём каждое исключение соблюдается только внимательностью, а промах не падает,
а тихо портит данные. Плата за отдельный словарь — четыре явные строки, которые видно
в диффе и которые невозможно «забыть наполовину».

Отдельный словарь ещё и ближе к тому, что уже написано: в коде он есть и работает.
Меняются только его ключи и состав.

**Что берётся из v2.2 без изменений:** расщепление `parentId` / `ownerId`, вынос камеры
в `state.levelViews`, стабильные идентификаторы, миграция на `formatVersion: 11`,
трёхсегментные межуровневые связи через прокси-порты, мастер-порт, кодировка полуколец,
огибание промежуточных окон, таблица порядка наложения, `pruneEmptyLevelWindows`,
перенумерация уровней.

## 2. Целевая модель данных (`formatVersion: 11`)

### 2.1. Окно уровня

```js
state.levelWindows['lvlwin-7f3a'] = {
  id: 'lvlwin-7f3a',          // стабильный, НЕ содержит номера уровня
  levelIndex: 1,              // производное поле, меняется при перенумерации
  name: 'Уровень 1: Потомки',
  content: '',
  color: '#0f172a',
  position: { x: -500, y: 380 },
  size: { w: 1000, h: 700 },
  fontFamily: 'Inter, sans-serif',
  fontSize: 14
};
```

Участвует в истории и экспорте. Камеры здесь нет.

### 2.2. Камера окна

```js
state.levelViews['lvlwin-7f3a'] = {
  innerOffset: { x: 0, y: 0 },
  innerZoom: 1.0,
  isCollapsed: false
};
```

Не участвует в истории (как `state.canvas`), но сохраняется в `localStorage` и в экспорт.

### 2.3. Узел и слой

```js
state.nodes['node-a1'] = {
  parentId: 'root',        // КООРДИНАТНЫЙ контейнер: 'root' или id слоя. НИКОГДА не узел и не окно
  ownerId: 'node-a',       // СЕМАНТИЧЕСКИЙ владелец: узел предыдущего уровня, или null
  position: { x: 40, y: 80 } // локальные координаты внутри холста своего уровня
};
```

Слой — то же самое: `parentId` ∈ {`'root'`, id другого слоя}, `ownerId` — узел-владелец или `null`.

### 2.4. 🔑 Правило вывода уровня

```
level(e) = e.parentId === 'root'
             ? (e.ownerId ? level(e.ownerId) + 1 : 0)
             : level(e.parentId)
```

Уровень **выводится, а не хранится**. Это сознательно сохранено из текущей реализации
и лучше, чем в v2.2: там `parentId` (окно) и `ownerId` хранились независимо и могли
разойтись, из-за чего v2.2 пришлось вводить проверку целостности «владелец ровно на уровень
выше». В выводимой модели такое расхождение невозможно в принципе.

### 2.5. Что это даёт координатам

Цепочка `parentId` больше **никогда** не пересекает границу уровня. Значит:

* `getLocalPosition(id)` — обычная сумма по `parentId` — **корректна по построению**;
* костыль `getLevelLocalPosition` («остановиться, если родитель — узел») **удаляется**;
* старая `getAbsolutePosition` перестаёт быть опасной: она и есть `getLocalPosition`.

Именно так Д2 закрывает Д1 сам собой, без ревизии девяти мест вызова.

### 2.6. Инварианты

1. Окна не вкладываются друг в друга и не лежат в `state.layers`.
2. Узел не может быть координатным родителем: `parentId` узла — только `'root'` или слой.
3. Слой не может содержать окно.
4. Уровень выводится по §2.4 и нигде не дублируется хранением.
5. `state.levelWindows` и `state.levelViews` имеют одинаковый набор ключей.
6. У каждого окна ровно один мастер-порт; его `id` производен от `id` окна, а не от номера.

## 3. Единая координатная математика

### 3.1. Метрики окна — один источник

```js
// hierarchy.js — рядом с ядром, чтобы не разъезжалось с CSS
const LEVEL_WINDOW_METRICS = { headerH: 40, borderW: 2 };
```

`LevelWindow.js` берёт `headerH` и толщину рамки **отсюда же**, а не из своих констант.
Сейчас `40` записано в двух файлах, а `border: 2px` не учтено в ядре вовсе — отсюда
постоянный сдвиг межуровневых связей на два пикселя (Д3).

### 3.2. Формула

```
local  = сумма position по цепочке parentId (только 'root' и слои)
win    = levelWindows[ windowIdOfLevel( level(e) ) ]
view   = levelViews[ win.id ]

world.x = win.position.x + borderW + view.innerOffset.x + local.x * view.innerZoom
world.y = win.position.y + borderW + headerH + view.innerOffset.y + local.y * view.innerZoom
scale   = view.innerZoom
```

Порядок слагаемых повторяет DOM буквально: `border-box` сдвигает содержимое на `borderW`,
шапка занимает `headerH`, вьюпорт имеет `transform: translate(innerOffset) scale(innerZoom)`.
Любое расхождение здесь — это инцидент 3 в новом обличье.

### 3.3. Публичное API `hierarchy.js` после ремонта

```js
getLocalPosition(id, nodes, layers)                     // сумма по parentId, без окон
getLevel(id, nodes, layers)                             // §2.4
getWindowOfLevel(levelIndex, levelWindows)              // окно по номеру уровня
getWorldTransform(id, state)                            // { x, y, scale } — ЕДИНСТВЕННОЕ ядро
getPortWorldPosition(portId, state)                     // { x, y } — для узловых и мастер-портов
getNodeWorldBounds(nodeId, state)                       // { x, y, w, h } с учётом scale
screenToWorld / worldToScreen(…, canvas, containerRect)
getProxyPorts(state)                                    // мемоизированный селектор
```

**Удаляются** (не переименовываются, а именно удаляются, чтобы их нельзя было позвать
по привычке): `getLevelLocalPosition`, `getPortWorldCoordinates`, `getMasterPortWorldCoordinates`,
`getEntityLevel`, `getPlainLayers`, `getLevelWindows` (последние два — мёртвый код).
`getAbsolutePosition` остаётся как псевдоним `getLocalPosition` только ради совместимости
с тестами миграции, с явным комментарием.

### Фаза 1. Расщепление `parentId` / `ownerId` и миграция на v11

Самая ответственная фаза: она чинит корневую причину.

- [ ] Ввести `ownerId` у узлов и слоёв, запретить `parentId`-указатель на узел.
- [ ] `FORMAT_VERSION = 11`, `STORAGE_KEY = 'architector_state_v11'`, прежний ключ читается
      как устаревший.
- [ ] `migrateToV11(data)` с **двумя ветвями** и явным различителем.

**🔴 Различитель обязателен.** Сегодня сборка Antigravity пишет `formatVersion: 10`, но
семантика координат у неё уже другая, чем у настоящего v10. Отличать так:

```js
const isHybrid = !!data.levelWindows;   // сборка Antigravity
const isLegacy = !isHybrid;             // исходный v10
```

Перепутать ветви — значит сдвинуть весь граф. Это надо покрыть тестом на обоих форматах.

**Ветвь «гибрид» (ваше текущее сохранение) — координаты не трогаются вовсе:**
1. для каждой сущности, у которой `parentId` указывает на узел: `ownerId = parentId`,
   `parentId = 'root'`; `position` остаётся как есть — она уже локальная;
2. окна получают стабильные `id`, `levelIndex` переезжает из ключа в поле;
3. камера переезжает из записи окна в `state.levelViews`.

**Ветвь «legacy v10» — координаты пересчитываются по уровням:**
1. посчитать старые абсолютные позиции всех сущностей (сумма по всей цепочке `parentId`,
   как это делал исходный `getAbsolutePosition`);
2. сгруппировать по уровню (старое правило: узел-родитель увеличивает уровень, слой — нет);
3. для каждого уровня взять габаритный прямоугольник и назначить локальные позиции как
   `старый_абсолют − минимум_габарита + отступ`;
4. `size` окна = габарит + отступ, `position` окна — по вертикальному каскаду;
5. `ownerId` = бывший `parentId`, если тот указывал на узел, иначе `null`.

Так взаимное расположение соседей сохраняется, а содержимое гарантированно попадает
внутрь рамки — то, чего сейчас нет и из-за чего демо-проект открывается пустым.

**Подводные камни:**

* 🔴 **`CREATE_NESTED_NODE` (`reducer.js:1212`) ставит `parentId` на узел-родителя.**
  Переписать на `ownerId`, иначе миграция будет чинить то, что код продолжает ломать.
* 🔴 **`REPARENT_ENTITY` (`reducer.js:1119`)** должен различать смену координатного контейнера
  (в слой и обратно) и смену уровня (смена `ownerId`). Это две разные операции, сейчас одна.
* 🔴 **`getChildrenStats`** — бейдж `📁 N` обязан считать по `ownerId`, а не по `parentId`,
  иначе счётчик молча покажет 0.
* 🟡 **`OutlinerTree` строит дерево по `parentId`** (`OutlinerTree.js:86`). Ему нужен новый
  порядок: уровень → окно → слои и узлы, а вложенность потомков показывать по `ownerId`.
* 🟡 **`resolveContextCollisions` группирует по `parentId`.** Теперь у всех узлов на всех
  уровнях `parentId === 'root'`, и узлы разных уровней начнут расталкивать друг друга.
  Группировать надо по паре `(level, parentId)`.
* 🟡 Каскадное удаление узла удаляет потомков по `ownerId`, а не по `parentId`.

* 🟡 В `localStorage` и в экспорт `levelViews` попадает, в снапшот истории — нет.
  Это разные вещи, их легко перепутать в одном спреде.

### Фаза 4. Трёхсегментные межуровневые связи

Приводим `Canvas.js:362-452` к §5.1 плана v2.2.

- [ ] Прокси-порты — мемоизированный селектор `getProxyPorts(state)` с детерминированными
      слотами: сортировка по целевому `levelIndex`, затем по `id` представляемого порта.
- [ ] Внутренние отрезки рисуются в локальном SVG своего окна и обрезаются рамкой.
- [ ] Магистральный отрезок рисуется в глобальном SVG и **начинается и заканчивается
      на рамке**, а не на порте узла.
- [ ] Огибание промежуточных окон по §5.5 v2.2 (две траектории, выбор короче, отступ 24px).
- [ ] Схлопывание слотов при более чем 8 связях на грани.
- [ ] Полукольца по §5.4 v2.2: число глифов = номер целевого уровня, уровень 0 — контрастный
      контур; на узле — по максимальной глубине, на рамке — точное число у каждого прокси.
- [ ] Дуги и прокси: `pointer-events: none` на дугах, прокси кликабельны.

**Подводные камни:**

* 🔴 Все три отрезка считаются **одной функцией**. Разведёшь по компонентам — получишь
  стык, разъезжающийся на каждом изменении масштаба.
* 🔴 Раскладка слотов не должна зависеть от `innerOffset`, иначе прокси поползут по рамке
  при внутренней панораме.
* 🟡 Прокси пересчитываются на каждый рендер, а во время протяжки связи `UPDATE_PENDING_CONNECTION`
  летит на каждый `mousemove`. Селектор обязан зависеть от `links`/`levelWindows`,
  но **не** от `pendingConnection`.
* 🟡 Прокси-порты и мастер-порт живут в необрезаемой обвязке рамки, а не во вьюпорте,
  иначе у них срежется половина.
* 🟡 Пунктир `2 6` при общем масштабе ниже ~0.3 сливается — нужен переход на тонкую сплошную.

## 5. Порядок и ожидаемый эффект

```
Фаза 0  Ловушки ──────────────► новые тесты ПАДАЮТ на текущем коде — это и есть цель
Фаза 1  ownerId + миграция ───► уровень выводится из ownerId, старые проекты открываются
Фаза 2  Одно координатное ядро► ✅ СВЯЗИ ЧИНЯТСЯ, сдвиг 2px уходит
```

**Главное про ожидания:** видимый результат «связи встали на место» появляется после

цепочка обязана где-то оборваться, и вторая формула вернётся.

## 6. Ручная приёмка

Помимо чек-листа v2.2 — то, что ловит именно найденные дефекты:

1. Связь между двумя узлами **на уровне 1** — концы точно в портах, а не смещены на позицию
   узла-родителя.
2. Слой на уровне 1 стоит там, куда его положили.
3. Межуровневая связь: концы точно в портах при `innerZoom = 1` (проверка сдвига на 2px).
4. Открыть `demo_project.json` — весь граф внутри рамок окон, ничего не обрезано.
5. Открыть сохранение текущей сборки Antigravity — граф не сдвинулся ни на пиксель.
6. Панорама и зум внутри окна → Ctrl+Z структурной правки **не сбрасывает вид**.
7. Undo после перемещения окна возвращает окно, а не только его содержимое.
8. Экспорт → очистка → импорт: окна, их номера, камеры и мастер-порты на месте.
9. Связь между уровнями 1 и 3 огибает окно уровня 2, прокси на уровне 2 не появляется.
10. Удалить уровень из середины: выделение, история и связи ассистента целы, номера пересчитаны.
11. Свернуть окно: мастер-порт на месте, прокси схлопнулись, связи ассистента не дрогнули.
12. Опустошить окно, к мастер-порту которого подключён ассистент, — окно **не** исчезает.
