## 0. Принятые и зафиксированные решения

| Развилка / Подсистема | Решение v2.2 |
|---|---|
| **Модель хранения окна** | **Разделение сущности и камеры:** рамка окна хранится в `state.layers` (`isLevelWindow: true`), а параметры камеры (панорама/зум/свёрнутость) — в `state.levelViews[id]` вне снапшотов истории по аналогии со `state.canvas`. |
| **Внутренняя панорама и зум** | Индивидуальные `innerOffset` и `innerZoom` для каждого окна в `state.levelViews`. Содержимое окна изолировано и обрезается контейнером с `overflow: hidden`. |
| **Узел и иерархия** | Расщепление полей узла: `parentId` = физический контейнер (id окна или id слоя), `ownerId` = семантический узел-родитель на верхнем уровне. Вложенность «узел внутри узла» упраздняется. |
| **Изоляция слоёв от окон** | Структурная фильтрация на входе: `HierarchyUtils.getPlainLayers` (обычные слои для `GeometryUtils`) и `HierarchyUtils.getLevelWindows` (только окна). |
| **Пустые окна** | Автоматически удаляются функцией `pruneEmptyLevelWindows(state)`, когда в них не осталось узлов и слоёв (включая окна в середине каскада). Окно уровня 0 не удаляется никогда. |
| **Перенумерация уровней** | Пакетный сдвиг `levelIndex` у окон ниже удалённого. Идентификаторы окон стабильны, поэтому выделение, изоляция и связи не страдают. |
| **Межуровневые связи** | Три отрезка через вычисляемые **прокси-порты** на рамках окон. Прокси-порт не хранится в состоянии, а вычисляется мемоизированным селектором. |
| **Мастер-порт уровня** | Ровно один хранимый мастер-порт на окно (`state.ports` с `isMaster: true`), расположенный на шапке окна. Не удаляется пользователем. |
| **Полукольца индикации уровня** | Общее число контуров = номер целевого уровня. На узле отображается максимальная глубина; на рамке у каждого прокси-порта — точное число дуг целевого уровня. |
| **Бросок связи в пустоту окна** | Создание нового узла с портом в точке отпускания (быстрое ветвление графа). Бросок на рамку окна подключает связь к мастер-порту уровня. |
| **Огибание окон связями** | Межуровневые связи, соединяющие несмежные уровни (например, L1 и L3), геометрически огибают промежуточные окна сбоку с безопасным зазором. |
| **Порядок наложения (z-index)** | Строгая многослойная шкала от `z-1` (окна) до `z-50` (плавающие панели управления). |

## 1. Архитектурный контекст и выученные уроки

Предыдущие попытки реализации выявили 4 фундаментальных риска, которые в версии v2.2 устранены на уровне архитектуры:

1. **Смешение состояния документа и состояния камеры:** Помещение `innerOffset`/`innerZoom` в `state.layers` приводило к откату зума и панорамы при любом `Undo/Redo` структурных действий. В v2.2 состояние камеры вынесено в `state.levelViews`.
2. **Нарушение инварианта системы координат:** Любые расхождения между DOM-трансформацией CSS и расчетными функциями JavaScript приводили к смещению точек привязки связей. В v2.2 введено единое ядро `getWorldTransform`.
3. **Хрупкость на отрицательных инвариантах:** Попытка внедрить окна в массив слоёв с ручной проверкой `if (!layer.isLevelWindow)` в 13+ местах влекла тихие регрессии. В v2.2 введена структурная фильтрация на входе `getPlainLayers`.
4. **Неопределённость жизненного цикла связанных сущностей:** Связи к удаляемым уровням, прокси-порты и мастер-порты теперь строго разграничены на хранимые (нормализуемые) и чисто производные.

### 2.2. Инварианты пространственной иерархии

1. **Окна не вкладываются друг в друга:** Все окна уровней имеют `parentId === 'root'`. Любая попытка перевложения отклоняется валидатором `REPARENT_ENTITY`.
2. **Узлы не содержат узлов:** Вложенность «узел внутри узла» упразднена. Детализация узла выносится на следующий уровень, где дочерние узлы получают `parentId = <id окна уровня>` и `ownerId = <id узла-родителя>`.
3. **Обычные слои изолированы внутри окон:** Обычный слой (`isLevelWindow: false`) может создаваться внутри окна (`parentId: lvlwin-id`), но не может содержать окна.

### 2.3. Формула преобразования координат (DOM & JS Parity)

Для произвольной сущности с локальной позицией `pos`:
```
Если сущность вне окон (parentId -> 'root'):
  worldPos = sum(position по цепочке parentId)
  worldScale = 1.0

Если сущность внутри окна W (через 0 или более вложенных слоев):
  localSum = sum(position по цепочке parentId вверх ДО окна W)
  worldPos = W.position + levelViews[W.id].innerOffset + (localSum * levelViews[W.id].innerZoom)
  worldScale = levelViews[W.id].innerZoom

Экранные координаты точки:
  screenPos = canvas.offset + (worldPos * canvas.zoom)
  screenScale = canvas.zoom * worldScale
```

### 2.4. Ядро координатных утилит в `hierarchy.js`

```js
// Получение мировой трансформации сущности с учетом масштаба окна
HierarchyUtils.getWorldTransform(id, nodes, layers, levelViews) 
// -> { x: number, y: number, scale: number }

// Совместимая обертка для аддитивной позиции (вызывает getWorldTransform)
HierarchyUtils.getAbsolutePosition(id, nodes, layers, levelViews)
// -> { x: number, y: number }

// Поиск окна-владельца сущности
HierarchyUtils.getOwningWindow(id, nodes, layers)
// -> LayerEntity (isLevelWindow: true) | null

// Определение владельца порта (узел или окно)
HierarchyUtils.getPortOwner(portId, state)
// -> { kind: 'node' | 'window', entity: NodeEntity | LayerEntity }

// Единственная точка правды для мировых координат порта
HierarchyUtils.getPortWorldPosition(portId, state)
// -> { x: number, y: number }

// Преобразование координат курсора
HierarchyUtils.screenToWorld(clientX, clientY, canvas)
HierarchyUtils.worldToScreen(x, y, canvas)

// Фильтрация слоев для устранения 13 ручных проверок
HierarchyUtils.getPlainLayers(layers)   // -> Record<string, LayerEntity> (без окон)
HierarchyUtils.getLevelWindows(layers)  // -> Record<string, LayerEntity> (только окна)
```

**Кэширование и инвалидация:**
`WeakMap`-кэш `getAbsolutePosition` / `getWorldTransform` валидируется по кортежу ссылок поколений: `(nodesRef, layersRef, levelViewsRef)`. Мутация `levelViews` (панорама/зум) гарантированно обновляет ссылку `state.levelViews`, вызывая мгновенную и точную инвалидацию кэша.

## 3. Реестр мест перевода на масштабозависимую математику

Каждая точка кодовой базы, работающая с координатами и масштабом, строго переводится на новый контракт:

| Модуль / Компонент | Текущий код | Целевой код v2.2 |
|---|---|---|
| `Node.js` (drag перемещение) | `delta / zoom` | `delta / (canvas.zoom * worldTransform.scale)` |
| `Node.js` (ручной ресайз) | `delta / zoom` | `delta / (canvas.zoom * worldTransform.scale)` |
| `Node.js` (порог скрытия деталей) | `zoom < 0.4` | `(zoom * worldTransform.scale) < 0.4` |
| `Port.js` (drag порта по периметру) | ручной пересчет `offset/zoom` | Доли `0.0..1.0` от `nodeElement.getBoundingClientRect()` |
| `Port.js` (хит-тест порта при drop связи) | `30 / zoom` в мире | Сравнение расстояния в экранных пикселях (радиус 18px) |
| `Port.js` (хит-тест дропа внутрь узла) | мировые координаты узла | `getWorldTransform` + `(size * scale)` |
| `Link.js` (`PendingLink`) | `(endPos - offset) / zoom` | `screenToWorld` + `getPortWorldPosition` |
| `Link.js` (толщина линии) | `strokeWidth: 2` | `vector-effect="non-scaling-stroke"` со сплошной компенсацией |
| `reducer.js` (`CENTER_ON_ENTITY`) | размер `size` в мире | размер `size * scale` с учетом `innerZoom` |
| `Canvas.js` (фоновая сетка) | `30 * zoom` глобально | внутри окна: `30 * zoom * innerZoom` |

## 5. Межуровневые связи, прокси-порты и мастер-порты

### 5.1. Трехсегментная модель межуровневой связи

Каждая межуровневая связь $L$ между портом узла $P_1$ в окне $W_1$ и портом узла $P_2$ в окне $W_2$ состоит из 3 синхронизированных отрезков:

1. **Внутренний источниковый отрезок:** От $P_1$ до прокси-порта $Proxy_1$ на границе окна $W_1$. Отрисовывается внутри локального SVG окна $W_1$ в локальных координатах и обрезается рамкой.
2. **Глобальный магистральный отрезок:** От $Proxy_1$ до $Proxy_2$ на границе окна $W_2$. Отрисовывается в глобальном SVG поверх окон. При наличии промежуточных окон линия геометрически огибает их.
3. **Внутренний целевой отрезок:** От прокси-порта $Proxy_2$ до порта узла $P_2$. Отрисовывается внутри локального SVG окна $W_2$.

### 5.2. Спецификация прокси-портов (Proxy Ports)

* **Чисто вычисляемые сущности:** Прокси-порты не сохраняются в `state.ports` и генерируются мемоизированным селектором `selectLevelWindowProxyPorts(layers, links, ports, nodes)`.
* **Стабильная раскладка слотов:** Слоты на гранях окон (Top, Bottom, Left, Right) распределяются детерминированно: сортировка по целевому `levelIndex`, затем по ID представляемого порта. Смещение панорамы внутри окна не заставляет прокси ползать по рамке.
* **Схлопывание при переполнении:** Если на одной грани окна концентрируется более 8 связей, смежные прокси-порты группируются в сводный слот с бейджем количества (например, `⚡ 4`).
* **Поведение при интерактивном дропе:** 
  * Дроп связи на прокси-порт создает связь с представляемым им удаленным портом узла.
  * Дроп на свободную область рамки подключает связь к мастер-порту уровня.
  * Попытки самосоединения и соединения прокси с прокси отклоняются.

### 5.3. Спецификация мастер-порта (Master Port)

* **Хранение в состоянии:** Хранится в `state.ports` с флагом `isMaster: true` и `windowId: win.id`.
* **Размещение:** Строго на фиксированной позиции в шапке окна рядом с индикатором уровня.
* **Защита от удаления:** Экшены `DELETE_SELECTED` и `REMOVE_PORT` игнорируют мастер-порты (`if (port.isMaster) return;`).
* **Сворачивание окна:** При `levelViews[win.id].isCollapsed === true` содержимое окна скрывается, а все межуровневые связи окна сходятся в мастер-порт с бейджем числа связей. Связи к мастер-порту от внешних ИИ-узлов и систем сохраняются неизменными.

### 5.4. Кодировка индикаторных полуколец (Level Depth Rings)

1. **Базовая шкала (Число глифов = Номер целевого уровня):**
   * Связь с **Уровнем 1:** 1 замкнутый контур вокруг порта.
   * Связь с **Уровнем 2:** 1 замкнутый контур + 1 наружная дуга (итого 2 слоя).
   * Связь с **Уровнем 3:** 1 замкнутый контур + 2 наружные дуги (итого 3 слоя).
   * Связь с **Уровнем 0 (Корень):** 1 замкнутый контур повышенной контрастности (акцентный цвет).
2. **Множественные связи на одном порте узла:**
   * На порте узла дуги отображаются по **максимальной глубине** (самой дальней цели) для сохранения чистоты интерфейса.
   * При наведении на порт всплывает подсказка со списком всех связанных уровней.
   * На рамках окон каждый индивидуальный прокси-порт отображает точное число дуг своего целевого уровня.
3. **Ограничение читаемости:** При номере уровня $> 4$ набор дуг заменяется на один контур с числовым бейджем `+N`. Все дуги имеют CSS-свойство `pointer-events: none`.

### 5.5. Алгоритм огибания промежуточных окон межуровневой связью

Если отрезок между $Proxy_A$ на окне $W_1$ и $Proxy_B$ на окне $W_3$ пересекает габаритный прямоугольник окна $W_2$:
1. Вычисляются две огибающие траектории (по левой и по правой стороне окна $W_2$ с внешним отступом 24px).
2. Выбирается траектория минимальной манхэттенской длины.
3. Отрезок строится как ортогональная полилиния со скруглением углов `rx: 8, ry: 8`.

## 6. Жизненный цикл уровней и каскадные операции

### 6.1. Автоматическое удаление пустых окон

Единая функция нормализации `pruneEmptyLevelWindows(state)` вызывается в завершении всех мутирующих экшенов (`DELETE_SELECTED`, `REMOVE_NODE`, `REMOVE_LAYER`, `REPARENT_ENTITY`, `MASS_UPDATE`):
1. Окно считается пустым, если в словаре `nodes` нет узлов с `parentId === win.id` (или вложенных в его слои), и в `layers` нет слоев с `parentId === win.id`.
2. **Окно уровня 0 не удаляется никогда.**
3. При удалении пустого окна:
   * Удаляется запись окна из `state.layers` и `state.levelViews`.
   * Удаляется его мастер-порт и каскадно все связи, подключенные к мастер-порту.
   * Выполняется пакетная перенумерация оставшихся уровней.
   * Все изменения фиксируются **в едином атомарном снапшоте истории**.

### 6.2. Пакетная перенумерация уровней

Поскольку `levelIndex` является полем объекта, а идентификаторы окон стабильны (`lvlwin-UUID`):
1. Для всех окон с `levelIndex > removedIndex` выполняется `levelIndex--`.
2. Все окна ниже удаленного смещаются по вертикали вверх на величину `(высота_удаленного_окна + 80px)`, устраняя пустоту на холсте.
3. Семантические ссылки `ownerId` на узлах проверяются: если владелец сместился вместе с уровнем, связь сохраняется; при разрыве целостности `ownerId` нормализуется.

## 7. Миграция данных v10 → v11

Функция `migrateToV11(data)` встраивается в `getInitialState` и обработчик `LOAD_STATE`:

```js
function migrateToV11(data) {
  if (data.formatVersion >= 11) return data;
  
  const layers = { ...(data.layers || {}) };
  const nodes = { ...(data.nodes || {}) };
  const levelViews = { ...(data.levelViews || {}) };
  
  // 1. Проверяем наличие окна уровня 0
  let rootWindow = Object.values(layers).find(l => l.isLevelWindow && l.levelIndex === 0);
  if (!rootWindow) {
    const rootWindowId = 'lvlwin-root-0';
    // Вычисляем охватывающий прямоугольник всех корневых элементов
    const bbox = calculateRootEntitiesBBox(nodes, layers);
    
    rootWindow = {
      id: rootWindowId,
      isLevelWindow: true,
      levelIndex: 0,
      name: 'Уровень 0: Основной',
      content: '',
      color: '#0f172a',
      position: { x: bbox.minX - 60, y: bbox.minY - 80 },
      size: { w: Math.max(900, bbox.width + 120), h: Math.max(650, bbox.height + 140) },
      parentId: 'root'
    };
    layers[rootWindowId] = rootWindow;
    levelViews[rootWindowId] = { innerOffset: { x: 0, y: 0 }, innerZoom: 1.0, isCollapsed: false };
    
    // Перевешиваем все корневые сущности на окно L0 с пересчетом относительных координат
    Object.values(nodes).forEach(node => {
      if (node.parentId === 'root' || !node.parentId) {
        nodes[node.id] = {
          ...node,
          parentId: rootWindowId,
          position: { x: node.position.x - rootWindow.position.x, y: node.position.y - rootWindow.position.y },
          ownerId: null
        };
      }
    });
    
    Object.values(layers).forEach(layer => {
      if (layer.id !== rootWindowId && (layer.parentId === 'root' || !layer.parentId)) {
        layers[layer.id] = {
          ...layer,
          parentId: rootWindowId,
          position: { x: layer.position.x - rootWindow.position.x, y: layer.position.y - rootWindow.position.y }
        };
      }
    });
  }
  
  // 2. Нормализуем мастер-порты
  const ports = ensureMasterPorts({ layers, ports: data.ports || {} });
  
  return {
    ...data,
    formatVersion: 11,
    layers,
    nodes,
    ports,
    levelViews
  };
}
```
