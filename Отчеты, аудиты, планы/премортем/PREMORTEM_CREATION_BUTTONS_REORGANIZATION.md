# Премортем-анализ: Реорганизация кнопок создания сущностей (FAB Toolbar & ContextActionBar)

**Дата:** 31 августа 2026  
**Цель анализа:** Выявление скрытых конфликтов, рисков рассинхронизации модели данных v11, проблем Undo/Redo и координатных скачков до начала реализации плана [PLAN_CREATION_BUTTONS_REORGANIZATION.md](../планы/PLAN_CREATION_BUTTONS_REORGANIZATION.md).

## 🚨 КРИТИЧЕСКИЙ РИСК №1: Различие `parentId` (контейнер) и `ownerId` (родство) при создании дочернего слоя на подуровне

### В чем проблема:
В модели данных v11 родство между уровнями выражается **только через `ownerId`**, а `parentId` служит исключительно координатным контейнером (`'root'` или ID слоя).
В `reducer.js` функция `normalizeContainer(entity, nodes)` проверяет:
```javascript
if (pid && pid !== 'root' && nodes && nodes[pid]) {
    return { ...entity, parentId: 'root', ownerId: pid };
}
```
Она превращает `parentId` в `ownerId` **только если родитель — это узел (`nodes[pid]`)**!
Если родителем является слой (`selectedLayer`), то `nodes[pid]` вернет `false`. В результате `parentId: selectedLayer.id` **не нормализуется**, и создаваемый слой станет физически вложенным подслоем внутри родительского слоя на том же уровне (координатное вложение), вместо того чтобы стать слоем-потомком на новом подуровне L{N+1}!

### Решение:
При создании дочернего слоя из панели свойств `ContextActionBar.js` явно передавать в экшен `ADD_LAYER`:
```javascript
dispatch({
    type: 'ADD_LAYER',
    payload: {
        name: `Слой (потомок «${selectedLayer.name || selectedLayer.id}»)`,
        position: pos,
        size: { w: 600, h: 400 },
        color: selectedLayer.color || '#ff9500',
        parentId: 'root',              // Координатный контейнер на новом уровне — всегда 'root'
        ownerId: selectedLayer.id      // Семантический владелец на уровне выше — исходный слой
    }
});
```

## 🚨 КРИТИЧЕСКИЙ РИСК №2: Отсутствие автоматического создания окна уровня (`LevelWindow`) для слоя

### В чем проблема:
* Для узлов экшен `CREATE_NESTED_NODE` в редьюсере содержит встроенную логику: проверяет наличие окна целевого уровня `targetLevel` и, если его нет, автоматически создает `levelWindows[newWinId]` и инициализирует камеру `levelViews[newWinId]`.
* Для слоев экшен `ADD_LAYER` в редьюсере **не создает окно уровня**. Если окно уровня L{N+1} еще не открыто, слой будет помещен в стейт, но окажется «невидимым» на холсте, так как у него нет пространственного окна `LevelWindow`.

### Решение:
В `ContextActionBar.js` при клике на «+» слоя проверять окно и при необходимости диспатчить `ADD_LEVEL_WINDOW` до создания слоя:
```javascript
const win = H && H.getWindowOfLevel(layerChildLevel, state.levelWindows);
if (!win) {
    dispatch({ type: 'ADD_LEVEL_WINDOW' });
}
```

## ⚠️ РИСК №3: Неатомарность Undo/Redo и координатный скачок при оборачивании узла в слой (`wrapNodeInNewLayer`)

### В чем проблема:
1. **История Undo:** Если последовательно вызвать `dispatch({ type: 'ADD_LAYER' })` и `dispatch({ type: 'UPDATE_NODE' })`, в истории будет записано два отдельных снимка. При первом нажатии `Ctrl+Z` узел выпадет из слоя в корень, а при втором — удалится слой.
2. **Координатный скачок узла:** Если узел находился близко к левому/верхнему краю (например, `x: 20`), а мы жестко зададим `layerPos.x = Math.max(0, node.x - 40) = 0` и локальную позицию узла внутри слоя `node.x = 40`, то мировая координата узла внезапно изменится с `20` на `40`. Это приведет к визуальному рывку узла и пересчету линий подключенных связей.

### Решение:
1. **Точный расчет координат без рывков:**
   ```javascript
   const paddingX = 40;
   const paddingY = 60;
   const nodePos = selectedNode.position || { x: 0, y: 0 };
   const layerPosX = Math.max(0, nodePos.x - paddingX);
   const layerPosY = Math.max(0, nodePos.y - paddingY);
   // Локальное смещение узла внутри слоя = разница между его исходной позицией и позицией слоя:
   const nodeInLayerX = nodePos.x - layerPosX;
   const nodeInLayerY = nodePos.y - layerPosY;
   ```
   В этом случае `layerPosX + nodeInLayerX === nodePos.x` с точностью до пикселя — узел и все его связи остаются на своих точных мировых координатах.
2. **Атомарность истории:**
   Вызывать `ADD_LAYER` с обычным сохранением истории, а `UPDATE_NODE` с флагом `skipHistory: true` (или использовать одиночный экшен/снапшот), чтобы операция откатывалась за один шаг `Ctrl+Z`.

## ⚠️ РИСК №4: Конфликт выделения при создании слоя вокруг узла

### В чем проблема:
При вызове `ADD_LAYER` редьюсер по умолчанию устанавливает `selectedIds: [newLayerId]`. Если после этого `UPDATE_NODE` сдвигает узел, что должно остаться выделенным?
* Если оставить выделенным слой: контекст переключится на панель слоя.
* Если вернуть выделение узлу: пользователь продолжит работу с узлом.

### Решение:
Оставить выделенным исходный узел (`selectedIds: [selectedNode.id]`) или новый слой — явно задать финальное выделение через `SET_SELECTED` после операции, чтобы фокус пользователя не терялся хаотично.

## ℹ️ РИСК №5: Сироты-якоря (`homeLevel`) и связи через поколение (`ownerGap`) при создании брата через FAB

### В чем проблема:
Если выделенный узел является главой независимой ветки (`homeLevel != null`) или имеет связь через поколение после очистки промежуточного уровня (`ownerGap > 1`), обычный брат узла обязан наследовать эти свойства, иначе он будет ошибочно усыновлен случайным узлом уровня выше.

### Проверка:
`HierarchyUtils.getAddContext(state)` уже корректно возвращает `anchorLevel` и `ownerGap` для выделенного узла, а функция `addNode()` в `Toolbar.js` уже передает `...(addCtx.anchorLevel != null ? { homeLevel: addCtx.anchorLevel } : {})` и `...(addCtx.ownerGap ? { ownerGap: addCtx.ownerGap } : {})`.
**Статус:** Риск полностью предотвращен текущей архитектурой `getAddContext`.

## Сводная матрица действий для Claude Sonnet

| Сценарий | Вызываемый экшен | Важные параметры / инварианты |
| :--- | :--- | :--- |
| **Клик по FAB (выделен узел)** | `ADD_NODE` | Создает брата через `getAddContext` (тот же `parentId`, `levelIndex`, наследует `ownerGap`/`homeLevel`) |
| **Клик по FAB (выделен слой)** | `ADD_NODE` | Создает узел внутри слоя (`parentId: selectedLayer.id`) |
| **Спутник «Слой» при узле** | `ADD_LAYER` + `UPDATE_NODE` (атомарно) | Точный пересчет `nodePos - layerPos`, узел не прыгает, `skipHistory: true` на втором шаге |
| **Панель свойств узла: «+»** | `CREATE_NESTED_NODE` | `{ parentId: selectedNode.id }` (автоматически создает окно подуровня и узел с `ownerId`) |
| **Панель свойств слоя: «+»** | `ADD_LEVEL_WINDOW` (если нет) + `ADD_LAYER` | `{ parentId: 'root', ownerId: selectedLayer.id }` — явно разделять контейнер и владение! |
