## 2. Что сделано по фазам

### Фаза 0 — измеримость

Создано с нуля, в проекте отсутствовало:

* `app/tests/fixtures/generate.js` — детерминированный генератор сцен (пресеты S=100 / M=500 / L=2000 узлов). Один seed → побайтово одинаковая сцена, прогоны сравнимы.
* `app/bench/core.bench.js` — замер чистой логики.
* `app/bench/render.bench.js` — замер перерисовок и FPS в headless-Chromium. Ключевая деталь методики: один `MOVE_SELECTED` **на кадр**; серия dispatch подряд схлопывается автоматической пакетизацией React и даёт картину, которой в реальной работе не бывает.
* `app/bench/syntax-check.js` — разбор всех JSX-файлов Babel до открытия страницы.
* `app/bench/offline-harness.js` — стенд с локальными копиями CDN-библиотек.
* `docs/BENCHMARKS.md` — baseline и результаты.

### Фаза 1 — регрессии и целостность

* Возвращена строка `REMOVE_PORT` / `REMOVE_LINK` в таблицу API `AGENTS.md` (была потеряна предыдущим заходом).
* `Port.js`: удалён мёртвый расчёт `isCrossLevel` — полный проход по всем связям, результат которого нигде не читался.
* `Node.js`: компонент переименован в `NodeView`, публикуется как `window.NodeComponent`. Прежнее объявление `function Node` затирало нативный DOM-интерфейс `Node`.
* `DELETE_SELECTED`: ре-якорение подопечных теперь работает и когда владельцем ветки был **слой** (набор `ownersToDelete` вместо только узлов).
* **Пакетная история** (`BEGIN_HISTORY_BATCH` / `COMMIT_HISTORY` / `CANCEL_HISTORY_BATCH`): весь ответ ИИ — один шаг Undo. Прежде каждая команда писала свой снимок, батч из 30+ команд вымывал лимит истории в 20 шагов, и отменить работу ассистента было невозможно в принципе. Механизм работает для любого экшена и не требует поддержки `skipHistory` в каждом.
* Лимит батча ИИ: 50 → **500**. Типовой запрос «схема из 15 узлов» — около 65 команд, то есть прежний лимит молча резал ответ пополам. Обрезка перестала быть молчаливой; лимит и правило подтверждения внесены в системный промпт ассистента (правила 10 и 11).
* Микро-регрессия массового поповера цвета: нативный пикер больше не закрывает поповер на каждом событии.

### Фаза 2 — движок подписок

`app/store/engine.js` — состояние вне React, компоненты подписываются через `useSyncExternalStore`.

* `useStore()` сохраняет прежний контракт `{ state, dispatch }` — ни один компонент не потребовал переписывания.
* `useSelector(selector)` — точечная подписка по **вычисленному** срезу.
* `useDispatch()`, `getStoreView()` (чтение без подписки для обработчиков).
* `dispatch` стабилен на всё время жизни приложения.
* Экшены-пустышки (редьюсер вернул то же состояние по ссылке) не будят подписчиков.
* `mergeActiveView` считается один раз на изменение, а не на каждый рендер.

Покрыто `app/tests/engine.test.js`.

### Фаза 3 — точечные подписки в горячих компонентах

* `Port`, `Node`, `Link` переведены на `useSelector` + `React.memo`; дети получают идентификаторы, а не записи, поэтому перерисовка родителя не тащит за собой поддерево.
* `getCrossLevelPortInfo` переведена на индекс `getLinksByPortId`: **102.21 мс → 0.68 мс** на сцене M (179×), на L — 2344 мс → 4.4 мс.
* `getLinkOrderIndex` — порядковый номер связи из кэша вместо `Object.keys(links).indexOf()`, дававшего O(связи²) на кадр.
* Исправлена ловушка в ключах кэша: литерал `layers || {}` создавал новый объект при каждом вызове, из-за чего кэш уровней промахивался **всегда**. Введена стабильная пустышка `EMPTY_DICT`.
* `app/tests/reactivity.test.js` — тесты «ряби»: перенос предка, смена владельца, удаление владельца с ре-якорением, `ownerGap`, «глаз» на L0 и на уровнях, подсветка сети через порты, состав межуровневых связей. Падают, если оптимизация потеряет затронутую сущность.

### Фаза 4 — сцены, жесты, связи неактивных проектов

* **Culling по вьюпорту** в `LevelWindow`: `getVisibleLocalRect` + `isRectVisible`, запас в один экран, безусловные исключения — участники жеста и выделенное. Критерий один — попадание на экран; активность проекта на качество отрисовки не влияет.
* `getProxyIndexForWindow` — прокси-порты окна по id связи с кэшем. Прежде `getProxyForLink` строил полный список прокси окна заново на каждую связь, дважды на каждую межуровневую: по профилю около половины процессорного времени кадра.
* Глобальный слой связей переведён на индекс межуровневых связей и кэшированный порядковый номер: **143.6 мс → 35.4 мс** на сцене L.
* `getEntitiesByLevel` — разложение сущностей по уровням одним проходом вместо полного перебора в каждом окне.
* Резолвер цели Drag&Drop — не чаще одного раза на кадр.
* **Межуровневые связи неактивных проектов** рисуются тем же компонентом (`CrossLevelLinkLayer`) и той же геометрией, что у активного. Проверено в браузере: 84 пунктирных сегмента на два проекта, переключение активного проекта число не меняет.

### Фаза 5 — массовое выделение контейнеров (новая функциональность)

* **Адресация:** `project:<projectId>`, `window:<windowId>` (по стабильному id окна — номер уровня не уникален между проектами). Легаси-формы `'project'` и `level-window-<N>` продолжают распознаваться: `selectedIds` персистится.
* **Классы взаимоисключающи:** `getSelectionClass` + `toggleSelectionWithClass`. Контейнеры и сущности графа не смешиваются, поэтому `DELETE_SELECTED` всегда однозначен.
* **Жесты:** Shift+клик по плашке проекта и по шапке окна набирает пачку; Shift по плашке не меняет активный проект.
* **Изоляция контейнеров** — вторая ось видимости, независимая от «глаза»: `containerIsolation: { projectIds, windowIds }`, функции `isContainerIsolationActive` / `isWindowVisible` / `isProjectVisible`. Кнопка живёт на самом контейнере (шапка окна, плашка проекта), поэтому выход из режима всегда на экране. Изоляция не входит в Undo и автоматически снимается при удалении изолированного контейнера (`pruneContainerIsolation`).
* **Панель контейнеров** в `ContextActionBar`: бейдж, счётчик, цвет, шрифт, изоляция, выравнивание, удаление. Оформление применяется **только к самим контейнерам** — содержимое не затрагивается.
* **Массовое удаление:** уровни сверху вниз по номеру (удаление поднимает нижние — при другом порядке номера разъедутся), вся пачка по проекту — один шаг Undo; Главный холст не удаляется; проекты удаляются целиком и необратимо, с диалогом-подтверждением.
* `FOR_PROJECT` — адресная доставка любого экшена в конкретный проект без смены активного.
* `app/tests/selection.test.js` — 10 тестов. Плюс живая проверка в браузере: набор пачки, панель, изоляция (3 окна → 1 → 3), массовое удаление (3 → 1 за один шаг истории), Undo (→ 3).

## 3. Изменения контракта, которые обязан знать любой агент

1. **Подписка по результату, а не по записи.** Новый компонент обязан считать производные значения в селекторе и сравнивать РЕЗУЛЬТАТ. Подписка вида `state.nodes[myId]` теряет «рябь» (перенос предка, смена владельца, «глаз», подсветка сети). Инвариант закреплён `reactivity.test.js`.
2. **Обработчики читают `getStoreView()` в момент события.** Замыкание на состояние времени рендера теперь опасно: компонент может не перерисовываться десятки кадров подряд.
3. **Классы выделения взаимоисключающи** — см. фазу 5.
4. **Изоляция контейнеров и «глаз» — разные оси.** Не смешивать в одном поле.
5. **Серия экшенов = один шаг Undo** через пакет истории. Использовать для любых массовых операций.
6. **История Undo не переживает перезагрузку страницы** (сознательный размен ради квоты `localStorage`).
7. **Компонент узла называется `NodeComponent`,** не `Node`.

## 5. Что НЕ сделано и почему

* **Ручная проверка интерфейса живыми руками не проводилась.** Автоматически проверены: тесты, типы, разбор JSX, загрузка страницы, три сценария в браузере (перерисовки, связи неактивных проектов, массовое выделение). Перед приёмкой стоит вручную прогнать драг узла, зум, создание связи от порта, перенос между уровнями и работу ИИ-агента.
* **Стратегический заход не входил в объём** и остаётся открытым: декомпозиция `reducer.js`, сборка вместо Babel Standalone, IndexedDB вместо `localStorage`, типизация контрактов экшенов, остаток декомпозиции `ContextActionBar`.
* **Профиль после работ плоский:** доминирующей функции нет, ~35% времени — простой, ~16% — внутренняя работа браузера. Запас оптимизации в текущей архитектуре выбран; дальнейший рост упирается в перечисленный выше стратегический заход.

## 6. Локальная работа без интернета (справка)

Приложение тянет с CDN пять внешних ресурсов: React, ReactDOM, Babel Standalone, Tailwind Play CDN, шрифт иконок Lucide (плюс десять семейств Google Fonts). Все они скачиваются без ограничений — для стенда `app/bench/offline-harness.js` это уже делалось.

Ориентировочный объём полностью локального комплекта: **~3.5 МБ** (Babel Standalone — 2.4 МБ, Tailwind — 407 КБ, Lucide woff2 — 230 КБ, ReactDOM — 132 КБ, React — 11 КБ, шрифты Google — по потребности).

Механизм подмены ссылок уже реализован в `offline-harness.js` (`CDN_MAP`) и переиспользуется для постоянной локальной сборки: файлы кладутся в `app/vendor/`, ссылки в `index.html` меняются на относительные. Zero-Build при этом сохраняется — Babel продолжает транспилировать в браузере.
