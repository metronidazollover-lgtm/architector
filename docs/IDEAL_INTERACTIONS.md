## 1. Единый источник родства: `parentId`

Каждая сущность (узел, слой) имеет **ровно одно** поле принадлежности — `parentId`. Значение одно из четырёх:

* `'root'` — сокращение для холста Главного холста (окно `lvlwin-root`, уровень 0);
* id окна уровня (`levelWindows` уже имеет стабильные id, например `lvlwin-a1b2c3`) — сущность является **сиротой-якорем**: у неё нет структурного родителя, но она явно привязана к холсту КОНКРЕТНОГО уровня N>0. Это единственная замена удалённому полю `homeLevel` — «домашний уровень» сироты закодирован прямо в значении `parentId`, а не в отдельном поле;
* id слоя — сущность лежит внутри слоя-контейнера (координатная группировка, уровень не меняется);
* id узла — сущность является содержимым подуровня этого узла (структурный шаг вверх на один уровень).

Полей `ownerId`, `ownerGap`, `homeLevel` в модели v13 не существует. Родство (кому подчинена сущность структурно) и координатная вложенность (где она физически нарисована) — это теперь **одно и то же** поле, а не два разных, как в v11/v12. Пространства id окон, слоёв и узлов не пересекаются — `parentId` разрешается однозначно через `levelWindows[pid] || layers[pid] || nodes[pid]`.

> **Почему не обойтись тремя значениями (`'root' | layerId | nodeId`).** Черновая формулировка главного плана называла только эти три — но тогда сирота-якорь без родителя на уровне N>0 (реальный, покрытый тестами сценарий: удаление промежуточного уровня пере-якоривает выживших потомков) имеет только `parentId: 'root'`, а чистое вычисление длины цепочки всегда даёт для него уровень 0 — то есть сирота при миграции незаметно съезжает на Главный холст. Явный id окна устраняет эту дыру, оставаясь при этом ОДНИМ полем: `parentId` — единственный источник и родства, и «домашнего» уровня.

### 1.1. Правило семантического шага (вычисление уровня)

Уровень сущности вычисляется рекурсивным подъёмом по цепочке `parentId`, пока не встретится терминальный случай — `'root'` или id окна уровня. Прохождение через слой не меняет уровень (только координатную группу), прохождение через узел — увеличивает на 1.

```
getEntityLevel(id):
    cur = entity(id)
    if !cur: return 0
    pid = cur.parentId
    if pid === 'root': return 0
    if levelWindows[pid]: return levelWindows[pid].levelIndex   // сирота-якорь: уровень задан явно окном
    if layers[pid]:  return getEntityLevel(pid)                  // слой — проходной, без инкремента
    if nodes[pid]:   return getEntityLevel(pid) + 1               // узел — семантический шаг
    return 0   // защитный fallback на битую ссылку
```

**Пример 1.** `Слой-A (root, L0) → Слой-B (внутри Слой-A) → Узел-X (внутри Слой-B)`: и Слой-A, и Слой-B, и Узел-X — все на уровне 0. Только сущность, чей `parentId` указывает на **узел** (т.е. лежащая на его подуровне), получает `level + 1`.

**Пример 2.** Сирота-якорь на уровне 2 (после удаления уровня 1, где раньше был её единственный предок): `parentId` = id окна уровня 2 напрямую. `getEntityLevel` возвращает `2` за один шаг, без цепочки промежуточных узлов — ровно то поведение, которое раньше обеспечивало поле `homeLevel`.

Это устраняет конфликт №1 премортема (см. таблицу в главном плане): без правила семантического шага два вложенных слоя ошибочно давали бы Узлу-X уровень L2 вместо корректного L0.

### 1.2. Защита от циклов (`isDescendantOf`)

Перед любым изменением `parentId` обязательна проверка:

```
isDescendantOf(candidateParentId, movingId, nodes, layers):
    // true, если candidateParentId лежит ВНУТРИ movingId (прямо или через цепочку)
```

Если `isDescendantOf(targetParentId, id) === true` — операция запрещена (нельзя вложить сущность в собственного потомка). Одна универсальная функция обслуживает и узлы, и вложенные слои — отдельных проверок для каждого типа не требуется.

## 2. Матрица операций для 6 сущностей

| Операция | Проекты | Уровни (окна) | Слои | Узлы | Порты | Связи |
|---|---|---|---|---|---|---|
| **Create** | `ADD_PROJECT` — новый проект правее существующих, пустой L0, становится активным | Окно уровня создаётся неявно при появлении первого узла на подуровне родителя (`CREATE_NESTED_NODE`) или явно кнопкой | На холсте уровня (`parentId: 'root'`) или внутри другого слоя | На холсте, внутри слоя, или как дочерний узел на подуровне узла-родителя (`parentId: <nodeId>` → открывает/создаёт окно уровня N+1) | На грани узла/слоя, `nodeId` = id владельца (легаси-имя поля, значение — узел или слой) | Только между двумя портами (`sourcePortId`/`targetPortId`) |
| **Move** (внутри контейнера) | — | Перетаскивание окна (`MOVE_LEVEL_WINDOW`) — не меняет содержимое | Изменение `position` без смены `parentId` | Изменение `position` без смены `parentId`, потомки следуют автоматически (относительные координаты) | Скольжение по периметру грани (`edge`/`position` 0..1) | Пересчитывается путь (`buildLinkPath`), сама связь не «двигается» |
| **Nest** (вложение) | — | — | Слой → в Слой (свободная вложенность любой глубины) | Узел → в Слой (группировка, уровень не меняется); Узел → в Узел (порождение/использование подуровня, уровень +1) | Следует за хостом | Пересоединение конца связи на другой порт |
| **Extract** (вытаскивание) | — | — | Слой → из родительского слоя на холст уровня (`parentId: 'root'`) | Узел → из слоя на холст того же уровня; Узел → с подуровня на уровень выше (меняет `parentId` на контейнер деда) | Следует за хостом | — |
| **Delete / Clear** | `REMOVE_PROJECT` — удаление целиком, необратимо (нет межпроектной истории) | `REMOVE_LEVEL_WINDOW` (N≥1, сдвиг нижних уровней вверх) / `REMOVE_ROOT_CANVAS` (L0) / `CLEAR_LEVEL_WINDOW` (только содержимое, окно остаётся) | Удаление слоя: Deep — вместе с содержимым; при удалении единственно самого слоя без Deep — содержимое переподчиняется `parentId` слоя (родителю слоя) | Аналогично слою: каскад (вся ветка) или всплытие детей к деду (см. §4 Shallow) | Каскадно удаляются с хостом | Каскадно удаляются при удалении любого из двух портов |
| **Connect** | — | Связь между узлом/слоем на разных уровнях допустима — рисуется сквозь границы окон | Слой участвует в графе связей наравне с узлом (порты на всех 4 гранях) | Локальные связи (тот же контейнер), сквозные связи (через уровни) | — | `sourcePortId` → `targetPortId`, любая комбинация узел/слой |

### 2.1. Move — детали

Перемещение — единственная операция, которая **не трогает `parentId`**, только `position`. Всегда безопасна, не требует проверки циклов, не участвует в Deep/Shallow (эти режимы касаются только Nest/Extract, то есть смены `parentId`).

### 2.2. Nest / Extract — общий контракт

Обе операции — это смена `parentId` целевой сущности (или группы сущностей). Разница только в направлении: Nest — `parentId` становится более «глубоким» контейнером (слой/узел), Extract — более «мелким» (обычно `'root'` уровня или родительский слой). В реализации это один и тот же экшен `REPARENT_ENTITY` (см. Фазу 4) — направление не требует отдельной ветки логики.

## 3. Тумблер безопасности Drag&Drop (`ui.dragDropMode`)

| | 🔒 Выключен (по умолчанию при каждой загрузке) | ⚡ Включён |
|---|---|---|
| **Перетаскивание на холсте** | Клампится рамкой своего окна уровня | Сквозное — через границы окон и уровней |
| **Смена `parentId`** | Заблокирована — жестом нельзя сменить контейнер за пределами группировки в слой своего уровня | Разрешена — вложение в узлы/слои, смена уровня |
| **Расталкивание слоёв** (`resolveLayerCollision`) | Активно — слои не наезжают друг на друга | Отключено на время жеста — иначе слой в слой не вложить |
| **Дерево Outliner** | Блокирует кросс-контейнерный сброс (подсказка «Включите Drag&Drop для смены уровня») | Свободно перевкладывает через `REPARENT_ENTITY` |
| **Deep / Shallow (Alt+Drag)** | Недоступно (перенос между контейнерами вообще запрещён) | Доступны оба режима |
| **Перенос между проектами** | Недоступен | Доступен (Фаза 6, `targetProjectId`) |

Тумблер — это единственный переключатель, разделяющий «безопасную расстановку на холсте» и «архитектурную перестройку иерархии». Он не влияет на Move (перемещение внутри контейнера безопасно всегда) — только на Nest/Extract.

## 4. Deep vs Shallow

Оба режима — варианты одного и того же экшена `REPARENT_ENTITY(ids, targetParentId, mode)`.

### 4.1. Deep (по умолчанию)

Сущность и вся её ветка потомков (по цепочке `parentId`) переезжают вместе — потомки **не меняют** свой `parentId`, они и так остаются детьми переносимой сущности, которая теперь просто в другом контейнере. Семантика — «переместить папку со всем содержимым».

### 4.2. Shallow (вырывание, модификатор `Alt`)

Переезжает **только** сама сущность. Её прямые дети (`parentId === movedId`) переподчиняются прежнему родителю переносимой сущности («усыновление дедушкой»):

```
REPARENT_ENTITY(id, targetParentId, mode: 'shallow'):
    oldParentId = entity(id).parentId
    directChildren = all entities where parentId === id
    for child in directChildren:
        child.parentId = oldParentId         // усыновление дедушкой
        child.position = findFreePosition(child, oldParentId)   // §4.3
    entity(id).parentId = targetParentId
```

Косвенные потомки (внуки и глубже) не трогаются вовсе — у них `parentId` не менялся, они остаются на своих местах вместе со своим прямым родителем.

### 4.3. Коллизия координат при всплытии

Ребёнок, усыновлённый дедом, физически появляется в новом контейнере на тех же локальных координатах `{x, y}`, где уже может стоять другая сущность. Каждый всплывающий ребёнок пропускается через `GeometryUtils.findFreePosition(child, targetContainer)`, которая находит ближайшую свободную позицию без наложения — та же функция, что уже используется при обычном добавлении узлов на слой (`getSmartPlacement`).

### 4.4. Атомарность истории

Перенос родителя, усыновление всех прямых детей и любой связанный с этим пересчёт связей — **один неделимый шаг Undo**. Один `Ctrl+Z` откатывает всю операцию целиком: и переехавшую сущность, и всех усыновлённых детей, и их новые позиции. Технически это то же требование, что уже реализовано для батчей истории ИИ-агента (`BEGIN_HISTORY_BATCH`/`COMMIT_HISTORY`) — `REPARENT_ENTITY` формирует один снимок состояния, а не серию отдельных мутаций.

### 4.5. Связи при Shallow

Связи не рвутся ни в каком случае. Если вырванный узел был соединён с одним из своих бывших прямых детей, связь просто становится связью между сущностями из разных контейнеров (как любая другая сквозная связь между уровнями/слоями) — `sourcePortId`/`targetPortId` не меняются, потому что порты остаются на своих хостах.

## 5. Визуальный фидбек при перетаскивании

| Ситуация | Индикатор |
|---|---|
| Обычный драг (Deep) над валидной целью | Бейдж на курсоре `[ 🌲 Ветка: N узлов ]` (N = размер поддерева, включая сам узел) |
| Драг с зажатым `Alt` (Shallow) | Бейдж `[ ✂️ Вырывание узла ]` |
| Курсор над допустимой целью сброса | Зелёный контур вокруг цели |
| Курсор над недопустимой целью (цикл, чужой уровень слоя, `dragDropMode` выключен) | Контур не подсвечивается / серый, drop не срабатывает |

Модификатор считывается **живо**, на всём протяжении жеста (`keydown`/`keyup`), а не только в момент `mouseup` — пользователь может зажать или отпустить `Alt` посреди перетаскивания, и бейдж должен обновиться немедленно.

## 6. Граничные случаи (Edge Cases)

1. **Слой в слое при подсчёте уровня.** См. §1.1 — уровень растёт только на узлах. Тест: `Слой(root) → Слой → Слой → Узел` — узел на L0, не на L3.
2. **Коллизия при Shallow-всплытии.** См. §4.3 — обязателен `findFreePosition`, иначе всплывшие дети слипаются в одной точке.
3. **Опустевшее окно уровня.** Если с уровня ушёл последний узел (например, все потомки перенесены Shallow-переносом), окно **не удаляется автоматически** — отображает пустое состояние с подсказкой «Уровень пуст». Закрывает его пользователь явно, крестиком `[X]` в шапке окна (`REMOVE_LEVEL_WINDOW`). Автоматическое схлопывание сломало бы порядок нумерации и камеры соседних уровней.
4. **Рассинхрон Undo/Redo.** См. §4.4 — перенос родителя и усыновление детей строго один шаг истории.
5. **Экспорт при внешних связях.** Локальный экспорт одного проекта: связь, второй конец которой лежит в другом проекте, не теряется молча — помечается `externalGateway: true` (виртуальный порт-шлюз), см. §7 главного плана. Вне области этого документа (относится к Фазе 6), упомянуто здесь для полноты матрицы «Connect».
6. **Случайный Shallow вместо Deep.** Единственная защита — визуальный бейдж (§5) и то, что Shallow требует **осознанного** удержания `Alt` в течение всего жеста; отпускание `Alt` до `mouseup` возвращает Deep.
7. **Попытка вложить сущность в саму себя или в своего потомка.** Блокируется `isDescendantOf` (§1.2) на уровне резолвера целей (`getDropTarget`) — цель не подсвечивается как валидная, drop не создаёт `REPARENT_ENTITY`.
8. **Слой чужого уровня.** Вложение узла в слой, физически лежащий на другом уровне (другая цепочка `parentId` до корня), запрещено — слой может принимать в себя только сущности своего уровня. Проверка — сравнение `getEntityLevel` слоя и переносимой сущности до применения переноса.
