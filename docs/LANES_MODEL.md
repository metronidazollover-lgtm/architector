## 0. Область действия

Документ формализует поведение четырёх сущностей — **Узел, Дорожка, Окно, Рамка** — и связей/портов между ними, а также двух сквозных механизмов: тумблера безопасности `ui.dragDropMode` и режимов переноса **Deep**/**Shallow**. Он не описывает визуальный дизайн (это `UX.md`) и не описывает формат хранения на диске (это `MIGRATIONS.md`) — только правила и математику взаимодействий.

Обоснование выбора этой модели (диагноз прежней архитектуры) — раздел 0.1 главного плана; здесь не повторяется.

## 1. Три сущности вместо одной запутанной

| Понятие | Что это | Где хранится |
|---|---|---|
| **Дорожка (lane)** | Внутренность одного узла (или корня проекта): вертикальная колонка, в которой лежат его прямые дети. `position` ребёнка считается от дорожки, то есть **от родителя**. | Не хранится — производная от `parentId`. |
| **Окно (window)** | Набор дорожек, положенных рядом: `[A | Б | Г]`. Окно одного узла = одна дорожка. Одна дорожка может быть показана в нескольких окнах (зеркала) — координаты у узла одни. | Состояние обзора, вне истории Undo (визуальные параметры) / в истории (структурные действия, см. §9). |
| **Рамка (frame)** | Множество узлов из любых дорожек: `{A1, Г1}`. Рисуется **кусками** — по одному bbox на дорожку, в которой есть члены. Узел может быть в нескольких рамках. Родства не имеет и не меняет. | Данные проекта, в истории Undo. |

Единственная структура родства во всей системе — `parentId ∈ {'root', nodeId}`. Рамка не может быть родителем ни для чего. Понятия из прежней модели — общий холст по глубине, сирота-якорь, «домашняя глубина», глобальный «глаз», отдельное поле активной глубины — в v14 не существуют.

### 1.1. Что сохраняется без изменений

Тумблер `ui.dragDropMode` (предохранитель), `REPARENT_ENTITY` с режимами `deep`/`shallow` (`Alt`), прокси-порты на рамке окна для межоконных связей, изоляция контейнеров (`containerIsolation`) для окон и проектов, движок `engine.js`/`Store.js`/`ProjectContext`, пакетная история (`BEGIN_HISTORY_BATCH`/`COMMIT_HISTORY`), мульти-проектность и кросс-проектные связи, отсечение по вьюпорту (culling).

## 2. Единственная структура: `parentId`

Каждый узел имеет ровно одно поле принадлежности — `parentId`, одно из двух значений:

* `'root'` — прямой потомок корня проекта (корневая дорожка);
* id узла — узел является содержимым дорожки этого узла-родителя.

### 2.1. Глубина (заменяет прежнее понятие уровня)

Глубина узла — длина цепочки `parentId` до `'root'`. Прямые дети корня — глубина 1, их дети — глубина 2 и так далее. Глубина не хранится — вычисляется рекурсивным подъёмом по `parentId` (`getDepth`). Рамка проходного шага не делает (в цепочке `parentId` рамок нет вообще — она не участвует в родстве).

```
getDepth(id):
    cur = node(id)
    if !cur: return 0
    if cur.parentId === 'root': return 1
    return getDepth(cur.parentId) + 1
```

### 2.2. Защита от циклов (`isDescendantOf`)

Перед любым изменением `parentId` обязательна проверка: `isDescendantOf(candidateParentId, movingId)` — true, если `candidateParentId` лежит внутри `movingId` (прямо или через цепочку `parentId`). Если true — операция запрещена (нельзя вложить узел в собственного потомка). Проверка обслуживает только узлы — рамки в родстве не участвуют, циклов через рамку не бывает.

### 2.3. Мировые координаты узла

Позиция узла складывается из трёх слагаемых: положение окна на холсте проекта (`window.position`, с учётом камеры `window.camera`), смещение дорожки его родителя внутри этого окна (порядковое место дорожки в списке `window.lanes`, ширина — константа `LANE_W`), и собственная `position` узла (локальная координата внутри дорожки). Дорожка узла может быть открыта в нескольких окнах одновременно (зеркала, статус реализации — см. §11.2) — тогда у узла несколько мировых позиций, по одной на каждое окно, при одних и тех же данных.

## 3. Нотация состояния

Формальный текстовый формат описания состояния проекта — обязательный инструмент всего перехода: он закрывает проблему «нельзя описать состояние в промпте или баг-репорте» и должен уметь печататься самим приложением (`HierarchyUtils.dumpNotation`) и парситься обратно в тестовую фикстуру (`HierarchyUtils.parseNotation`).

```
ДЕРЕВО            ОКНА                       РАМКИ                   СВЯЗИ
/A                W1 = [Проект]              Датчики = {A1, Г1}      A1.out → Г1.in
/A/A1             W2 = [A | ~Б | Г]          Питание = {Б1, A1_2}    Б.p2 → Б1.p1
/A/A1/A2          W3 = [A1]
/Б/Б1             W5 = Датчики ⊂ [A | Г]     (~ — дорожка скрыта; ⊂ — окно рамки)
```

Правила:
* **ДЕРЕВО** — путь узла = цепочка имён по `parentId`, от корня (`/`) до узла; глубина = длина пути.
* **ОКНА** — окно = упорядоченный список дорожек через `|`, в порядке `window.lanes`; `~ИмяДорожки` — дорожка скрыта («глаз»); `ИмяРамки ⊂ [...]` — окно рамки (см. §1, `frameId`), список — дорожки, в которых есть видимые члены рамки.
* **РАМКИ** — рамка = множество узлов в фигурных скобках, порядок не важен.
* **СВЯЗИ** — `узел.порт → узел.порт` (или `рамка.порт`, если порт принадлежит рамке).

Баг-репорт для агента (человека или ИИ) в этой нотации оформляется как `было / делаю / жду / получил`. Кнопка «Скопировать состояние» в тулбаре и системный промпт ИИ-агента (`AIAgentNodeContent.js`) используют эту нотацию вместо сырого JSON.

## 4. Модель данных v14 (контракт для Фазы 1)

### 4.1. Узел
```js
{ id, name, content, color, icon, mediaUrl, fontFamily, fontSize, size, shape, type,
  parentId: 'root' | nodeId,
  position: { x, y },               // от дорожки родителя (= от родителя)
  snapToGrid, userResized, ... }
```
Полей `ownerId`, `ownerGap`, `homeLevel`, и `parentId`, указывающего на рамку или на окно, в v14 не существует.

### 4.2. Рамка (`frames`)
```js
{ id, name, content, color, fontFamily, fontSize,
  members: [nodeId, ...],           // множество; порядок = порядок добавления
  homeLaneId: 'root' | nodeId,      // дорожка «первого куска»: имя, счётчик, ⧉ и порты
  snapToGrid }
```
Рамка не имеет `position`/`size` и не имеет `parentId`. Кусок рамки в дорожке = bbox её членов в этой дорожке + отступ; вложенные рамки рисуются со ступенчатым отступом друг от друга. Порты рамки (`ports[].nodeId === frame.id`) привязаны к куску в `homeLaneId`; если в домашней дорожке членов нет — порты временно рисуются на первом непустом куске, само поле `homeLaneId` при этом автоматически не переписывается.

**Межпроектные рамки.** `members` рамки может содержать узлы из разных открытых проектов. Обычная рамка (все члены в одном проекте) хранится в `state.projects[pid].frames` и участвует в истории Undo этого проекта, как описано выше. Рамка, у которой хотя бы два члена принадлежат разным проектам, хранится вне какого-либо одного `state.projects[pid]` — по аналогии с `crossProjectLinks` — и сама целиком (создание, изменение членства, удаление) вне истории Undo любого из проектов, см. §9.1.

### 4.3. Окно (`windows`)
```js
{ id: 'win-…', lanes: [ownerId, ...], hidden: [ownerId, ...],
  frameId: null | frameId,          // окно рамки: показаны только её члены
  position: { x, y }, size: { w, h },   // на мировом холсте
  camera: { offset, zoom },
  collapsed, name, color, fontFamily, fontSize }
```
`ownerId` в `lanes`/`hidden` — `'root'` либо id узла, чья дорожка открыта. Инвариант: дорожка отображается только если её открыли явно; узел без открытой дорожки родителя не отображается и не участвует в рендере.

### 4.4. UI-состояние проекта
`activeLaneId` (последняя дорожка, по которой кликнули; контекст для FAB «+»), `dragDropMode`, `dragGesture`, `selectedIds` (узлы, рамки, окна, проекты), `activeFrameId` (рамка, подсвеченная кликом по её ярлыку; не в истории).

### 4.5. Что удаляется из состояния v13
`levelWindows`, `levelViews`, `levelHideNeighbors`, `levelFocusParentId`, `activeLevelIndex`, `layers` (заменяются на `frames`), `LEVEL0_WINDOW_ID`.

## 5. Матрица операций

| Операция | Узел | Рамка | Окно | Дорожка |
|---|---|---|---|---|
| **Create** | Новый узел — в активную дорожку (`activeLaneId`) или явным `parentId`; вложенный узел = новый узел с `parentId: nodeId`, при необходимости открывающий дорожку родителя | Двойной режим по наличию выделения в момент создания: есть выделение карточек → рамка сразу с этими членами; нет выделения → пустая рамка, наполняется последующими дропами. Без диалога — имя/цвет автоматические, правятся потом в панели свойств (см. §12.6) | Открытие дорожки, не показанной ни в одном окне, создаёт для неё новое окно | Производная — своего экшена создания нет, появляется вместе с первым открывшим её окном |
| **Move** | `position` в пределах дорожки; тумблер безопасности не требуется | Нет отдельного перемещения — кусок следует за членами; перетаскивание ярлыка куска двигает самих членов | Перетаскивание/масштабирование/панорама/зум окна на холсте — визуальное, содержимое не меняет | Стыковка к другому окну, отстыковка в своё окно, смена порядка внутри окна |
| **Nest / Extract** | Смена `parentId` на узел (вложение) или на `'root'` (извлечение) — через границу дорожки, дроп на карточку узла, дроп в окно другого проекта | Добавление / удаление членства узла в рамке (дроп в кусок, клик по чипу) | — | — |
| **Delete / Clear** | Каскад всей ветки (по умолчанию) или сохранение детей — прямые дети переходят к деду с автоматическим разведением коллизий | Удаление самой рамки — узлы остаются нетронутыми; каскадно удаляются только порты и связи рамки | Закрытие окна — только обзор, данные узлов/рамок не меняются | Скрытие дорожки («глаз», сжатие в полоску) или закрытие дорожки из конкретного окна |
| **Connect** | Порт ↔ порт любых узлов, в любых открытых окнах и проектах; связь между окнами идёт через прокси-порт на рамке окна | Порты только на куске домашней дорожки (`homeLaneId`) | — | — |

### 5.1. Move — уточнение

Перемещение узла внутри своей дорожки — единственная операция, не меняющая `parentId` (только `position`); тумблер `ui.dragDropMode` на неё не влияет, проверка циклов не нужна, Deep/Shallow к ней не применимы (эти режимы касаются только Nest/Extract).

### 5.2. Nest / Extract — общий контракт

Обе операции — смена `parentId` целевого узла (или группы). Технически это один и тот же экшен `REPARENT_ENTITY({ ids, targetParentId: nodeId | 'root', mode, position })` — направление (вглубь или к корню) не требует отдельной ветки логики. `targetParentId`, указывающий на рамку или на окно, недопустим.

## 6. Тумблер безопасности Drag&Drop (`ui.dragDropMode`)

| | 🔒 Выключен (по умолчанию при каждой загрузке) | ⚡ Включён |
|---|---|---|
| **Перетаскивание карточки** | Клампится границей своей дорожки: карточка мягко останавливается на границе и скользит вдоль неё, пока курсор её ведёт (без резкого отскока) | Сквозное — дроп на другую карточку, в другое окно, в другой проект |
| **Смена `parentId`** | Заблокирована | Разрешена — Nest/Extract доступны |
| **Дроп на карточку узла** | Не вкладывает | Вкладывает; если у карточки-цели ещё нет открытой дорожки — она открывается автоматически, чтобы результат был виден |
| **Дерево Outliner** | Блокирует кросс-контейнерный сброс | Свободно перевкладывает через `REPARENT_ENTITY`, поддерживает перенос нескольких выделенных строк одним жестом |
| **Deep / Shallow (`Alt`)** | Недоступны (перенос вообще запрещён) | Доступны оба, режим читается живо весь жест (можно нажать/отпустить `Alt` посреди перетаскивания) |
| **Перенос между проектами** | Недоступен | Доступен, без дополнительного подтверждения — так же просто, как перенос внутри одного проекта |

Тумблер фиксируется на старте жеста и не переживает перезагрузку страницы. Он не объединяется с модификатором `Alt` (Deep/Shallow) — это два независимых механизма, один разрешает/запрещает Nest/Extract целиком, второй выбирает его режим.

## 7. Deep vs Shallow

Оба режима — варианты одного и того же экшена `REPARENT_ENTITY(ids, targetParentId, mode)`.

### 7.1. Deep (по умолчанию)

Узел и вся его ветка потомков (по цепочке `parentId`) переезжают вместе — потомки не меняют `parentId`, они остаются детьми переносимого узла, который теперь в другой дорожке. Семантика — «переместить папку со всем содержимым».

### 7.2. Shallow (вырывание, модификатор `Alt`)

Переезжает только сам узел. Его прямые дети переподчиняются его прежнему родителю («усыновление дедушкой»), с авторазведением коллизий позиций (`findFreePosition`) в дорожке деда:

```
REPARENT_ENTITY(id, targetParentId, mode: 'shallow'):
    oldParentId = node(id).parentId
    directChildren = all nodes where parentId === id
    for child in directChildren:
        child.parentId = oldParentId
        child.position = findFreePosition(child, oldParentId)
    node(id).parentId = targetParentId
```

Косвенные потомки (внуки и глубже) не трогаются — их `parentId` не менялся.

### 7.3. Атомарность истории

Перенос узла, усыновление всех прямых детей и любой связанный с этим пересчёт позиций — один неделимый шаг Undo.

### 7.4. Связи при Shallow

Связи не рвутся никогда. Если вырванный узел был соединён с одним из бывших прямых детей, связь становится связью между узлами из разных дорожек — `sourcePortId`/`targetPortId` не меняются, потому что порты остаются на своих хостах.

## 8. Визуальный фидбек при перетаскивании

| Ситуация | Индикатор |
|---|---|
| Обычный драг (Deep) над валидной целью | Бейдж `[ 🌲 Ветка: N узлов ]` |
| Драг с зажатым `Alt` (Shallow) | Бейдж `[ ✂ Вырывание ]` |
| Тумблер выключен, попытка вытащить за границу дорожки | Карточка мягко останавливается на границе и скользит вдоль неё, бейдж `🔒` |
| Курсор над допустимой целью сброса (дорожка / карточка / кусок рамки) | Контур подсвечен |
| Курсор над недопустимой целью (цикл, тумблер выключен) | Контур не подсвечивается, drop не срабатывает |

Модификатор `Alt` считывается живо на всём протяжении жеста, а не только на `mouseup`.

## 9. История Undo — что входит, что нет

### 9.1. Проектная история

**Вне истории** (чисто визуальные параметры обзора): `MOVE_WINDOW`, `RESIZE_WINDOW`, `PAN_WINDOW`, `ZOOM_WINDOW` — движение и масштабирование окна по холсту, camera окна.

**В истории** (наравне с изменением данных, несмотря на то что сами `nodes`/`frames` не меняются — ради предсказуемости для пользователя): `OPEN_LANE`, `CLOSE_LANE`, `DOCK_LANE`, `DETACH_LANE`, `OPEN_FRAME_WINDOW`, `CLOSE_WINDOW`, `TOGGLE_WINDOW_MAXIMIZE`, `NEW_EMPTY_WINDOW`, а также любые действия над узлами и обычными (не межпроектными) рамками (`REPARENT_ENTITY`, `ADD_FRAME`, `FRAME_ADD_MEMBERS`/`FRAME_REMOVE_MEMBERS`, `REMOVE_FRAME`, `REMOVE_NODE` и т.д.).

Правило дистилляции: «дорожка/окно» — это где узел *показан*, а не то, что определяет его существование или его связи. Закрытие окна не трогает данные: связи между узлами, чьи дорожки были в закрытом окне, сохраняются и снова отрисовываются, как только эти дорожки где-либо открыты. Случайно закрытое окно возвращается двумя равноценными способами: кнопкой «Отменить» или вручную (открыть каждую дорожку заново через бейдж на карточке).

### 9.2. Исключение: межпроектная рамка

Рамка, объединяющая узлы из разных проектов (§4.2, §12.7), — не проектные данные ни одного из них: она хранится вне `state.projects[pid]`, по аналогии с `crossProjectLinks`. Любое действие над такой рамкой целиком (создание, `FRAME_ADD_MEMBERS`/`FRAME_REMOVE_MEMBERS`, `REMOVE_FRAME`) идёт **вне истории Undo** любого из задействованных проектов — тем самым это единственное исключение из правила §9.1 «действия над рамками — в истории». Рамка, все члены которой лежат в одном проекте, под это исключение не подпадает и остаётся в истории Undo этого проекта.

---

## 10. Окна — детали поведения

1. **Разворот на весь экран.** Кнопка на шапке окна (`TOGGLE_WINDOW_MAXIMIZE`) временно растягивает окно на весь вьюпорт; повторное нажатие возвращает прежние `position`/`size`.
2. **Раскладка новых окон.** Окна ставятся в колонки по глубине; новое окно — под последним окном своей колонки. Переполнение колонки за край экрана не компонуется автоматически — пользователь скроллит и двигает окна руками.
3. **Перекрытие.** Разрешено — окна могут наезжать друг на друга. Активное/захваченное для перетаскивания окно поднимается поверх остальных на время взаимодействия.
4. **Пустое окно про запас.** Окно, опустевшее *в результате* `DETACH_LANE`/`DOCK_LANE`, закрывается автоматически. Отдельно доступно намеренное создание пустого окна, не привязанного ни к одной дорожке (`NEW_EMPTY_WINDOW`) — оно не закрывается само, пока пользователь не закроет его вручную.
5. **Минимальный размер.** `RESIZE_WINDOW` не даёт сжать окно меньше размера одной карточки.
6. **Полностью свёрнутое окно.** Если все дорожки внутри окна скрыты «глазом» по отдельности — само окно тоже схлопывается в тонкую полосу.
7. **Корневая дорожка не особенная.** Над ней доступны все те же действия, что и над любой дорожкой (свернуть, отстыковать, закрыть). Тупика «холст пуст, кликать не на чем» при этом не возникает: обозреватель проекта (`Library`/`OutlinerTree`) — отдельная постоянная панель, не зависящая от того, что открыто на холсте, и клик по любому узлу с детьми там всегда открывает его дорожку (включая корень). Отдельная кнопка «Показать корень» не нужна.

---

## 11. Дорожки — детали поведения

1. **Дроп на свёрнутую дорожку.** Если перетаскиваемый узел наведён на дорожку, свёрнутую «глазом» — она автоматически разворачивается и принимает узел, вместо того чтобы отклонять дроп до ручного разворачивания.
2. **Зеркала (одна дорожка в нескольких окнах).** Статус открыт — сценарий встречается ли в реальной работе, не подтверждено. Реализация зеркал в первой версии перехода не обязательна; описание в §1/§4.3 не убирается, но не является блокером готовности MVP.
3. **Персистентность пустой дорожки.** Дорожка, у узла которой не осталось детей, но которая была открыта явно, при сохранении/загрузке проекта остаётся открытой (пустой, с подсказкой «брось сюда узел»), а не закрывается тихо при перезапуске.

---

## 12. Рамки — детали поведения

1. **Вложенные рамки на одной карточке.** Если карточка обведена сразу несколькими рамками — контуры вложенные (один внутри другого), каждый своим цветом.
2. **Удаление карточки из нескольких рамок сразу.** Без предупреждения — карточка тихо убирается из `members` всех рамок, в которых состояла (это только группировка, не структура).
3. **Глубина вложенности рамок.** Без ограничения — читаемость на ответственности пользователя.
4. **Опустевшая рамка.** Если из рамки убрали всех членов одного за другим — она не удаляется автоматически, остаётся именованной цветной заготовкой (`name`/`color` сохранены), которую можно снова наполнить; удаляется только явным `REMOVE_FRAME`.
5. **Перенос порта при смене `homeLaneId`.** Если домашняя дорожка рамки переназначена вручную — связи, входящие в порты рамки, мгновенно перескакивают на новый кусок, без анимации перехода.
6. **Создание — переиспользуется существующая кнопка.** Новой кнопки в тулбаре/FAB не заводится: та же кнопка, что раньше создавала прежний координатный контейнер (переименовывается в «Рамка» вместе с переходом), теперь создаёт рамку. Поведение зависит от того, есть ли выделение карточек в момент клика — есть выделение → рамка сразу с этими карточками в `members`; нет выделения → пустая рамка, наполняется вручную последующими дропами. В обоих случаях имя и цвет — автоматические, без диалога ввода; правятся потом через панель свойств рамки.
7. **Межпроектная рамка.** Рамка может объединять узлы из разных открытых проектов (`members` содержит id узлов с разными владеющими проектами). Такая рамка хранится вне `state.projects[pid]` любого из них (аналогично `crossProjectLinks`) и целиком — создание, изменение членства, удаление — вне истории Undo любого проекта (см. §9.1). Рамка, все члены которой лежат в одном проекте, ведёт себя как обычно (§4.2) и остаётся в истории Undo этого проекта, даже если раньше в ней были межпроектные члены.

## 13. Поиск и навигация

Строка поиска по имени узла — в дереве обозревателя проекта (`OutlinerTree`), а не отдельным оверлеем поверх холста. Отдельная мини-карта холста не предусмотрена — навигации зумом колёсиком достаточно.

## 14. Граничные случаи (Edge Cases)

1. **Цикл при `REPARENT_ENTITY`.** Блокируется `isDescendantOf` (§2.2) на этапе резолвера цели — цель не подсвечивается как валидная, drop не создаёт действие.
2. **Коллизия при Shallow-всплытии.** Обязателен `findFreePosition` в дорожке деда (§7.2), иначе всплывшие дети слипаются в одной точке.
3. **Удаление узла с открытой дорожкой.** Если у удаляемого узла была открыта дорожка и она была единственной в своём окне — окно закрывается вместе с узлом.
4. **Рамка, все члены которой скрыты «глазом».** Рисуется ярлык-заглушка на первом непустом (по видимости) куске; если видимых членов нигде нет — рамка в окне не рисуется вовсе.
5. **Зеркало дорожки при перетаскивании.** `dragGesture` привязан к окну-источнику жеста; остальные зеркала (если реализованы, см. §11.2) перерисовываются по данным после отпускания.
6. **Окно рамки при удалении рамки.** Закрывается вместе с удалением рамки (`REMOVE_FRAME`).
7. **Дроп в окно рамки.** Родителем становится дорожка под курсором (как в обычном окне); дополнительно узел добавляется в членство рамки этого окна.
8. **Атомарность Undo/Redo для составных операций.** Перенос узла с усыновлением детей (§7.3), пакетная фиксация действий ИИ-агента (`BEGIN_HISTORY_BATCH`/`COMMIT_HISTORY`) — строго один шаг истории на операцию.
9. **Попытка задать `parentId` на рамку или на окно.** Недопустимо в любом пути создания/переноса — единственные значения `'root' | nodeId` (§2).

## 15. Явно снятые с рассмотрения вопросы

* **Отчёт о миграции старых файлов** (импорт v11–v13 → v14) не нужен — результат просто показывается на холсте, без отдельной сводки.
* **«Ленты»** (табличная матрица родитель × группа) — идея снята с рассмотрения насовсем, в будущем не планируется.
* **Переполнение вывода нотации** для ИИ-агента на очень больших деревьях — закрывается настройками самого агента, отдельного проектирования в v14 не требует.
