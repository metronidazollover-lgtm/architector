## 2026-08-31 (3) — Фаза 6.3: кросс-проектный перенос сущностей живым Drag&Drop

- **`HierarchyUtils.getDropTarget`/`computeDropPositions`/`canReparentTo`:** новый необязательный параметр (`sourceState`/`entityDicts`) — «откуда взять перетаскиваемых» отделено от «в чьих словарях искать цель»; без аргумента поведение не меняется (обратная совместимость с внутрипроектным путём). Заодно исправлен латентный баг: «своё окно» (`isMove`) теперь определяется совпадением id окна, а не номера уровня — у кросс-проектного дропа уровень цели мог случайно совпасть с уровнем источника, оставаясь другим окном.
- **`HierarchyUtils.getDropTargetAcrossProjects(draggedIds, pointerWorld, multiState, sourceProjectId, opts)`:** сканирует все открытые проекты (кроме скрытых изоляцией) через `getDropTarget`, лучший результат — по приоритету node > layer > window; возвращает `projectId` найденной цели.
- **Жест в `Node.js`/`Layer.js`:** `computeTarget` вызывает `getDropTargetAcrossProjects` вместо `getDropTarget`; на `mouseup`, если цель в другом проекте, `REPARENT_ENTITY` получает `sourceProjectId`/`targetProjectId`. Deep/Shallow (Alt) работают одинаково в обоих случаях — никакого сужения до Deep-only.
- **`applyCrossProjectReparent(m, payload)`** в `multiReducer`: перехватывает `REPARENT_ENTITY` с разными `sourceProjectId`/`targetProjectId`, собирает ветку (сущность + структурные потомки, порты, внутренние связи) из исходного проекта, при Shallow — переприкрепляет прямых детей к деду ВНУТРИ него, вставляет в целевой (`findFreePosition` на корне цели), переписывает `crossProjectLinks`/`pendingGateways` уехавших портов на новый `projectId`. Не участвует в Undo ни одного из проектов.
- **Подсветка цели по `projectId`:** `Node.js`/`Layer.js`/`LevelWindow.js` при матчинге `dragGesture.target` (глобальное поле) теперь сверяют и проект — иначе гипотетическое совпадение id между проектами подсветило бы не тот узел.
- **Тестирование:** +8 юнит-тестов (`app/tests/projects.test.js`): Deep-перенос узла и ветки, Shallow с усыновлением детей дедом, перенос переписывает `crossProjectLinks`/`pendingGateways`, рост нового уровня в целевом проекте через `targetParentId`-узел, no-op на несуществующем проекте, `getDropTargetAcrossProjects` (node/window, регрессия на «то же levelIndex, другое окно»), `computeDropPositions` с `sourceState`. Итого 248 юнит-тестов, 100% PASS; `tsc` — без новых ошибок (заодно на 1 меньше в Store.js: `getProjectFlatView` добавлен в `types/globals.d.ts`, понадобился новому коду в `hierarchy.js`). Живая проверка в браузере: прямой вызов `getDropTargetAcrossProjects`/диспатч `REPARENT_ENTITY` с реальным browser-loaded кодом подтвердил перенос узла между двумя живыми проектами на холсте (полный live-жест мышью через синтетические DOM-события не проверен — `requestAnimationFrame`, на который завязан троттлинг резолвера цели, не тикает в этой скрытой browser-панели; сама логика резолвера и редьюсера проверена и юнит-тестами, и прямым вызовом в живом браузере).

## 2026-08-31 (2) — Фаза 6.2: `externalGateway` — экспорт разрыва и автопримирение штекеров

- **`project.pendingGateways`:** новый `PROJECT_FIELD` — «висящие штекеры», непримирённые половины кросс-проектных связей. Ключ — `linkId` исходной живой `crossProjectLinks`-записи (опорный идентификатор для последующего примирения).
- **Локальный экспорт (`ContextActionBar.js`/`handleExportProject`):** файл экспортируемого проекта дополняется `externalGateways` — по одной записи на каждую `crossProjectLinks`, задевающую этот проект (иначе половина связи молча терялась бы при экспорте одного проекта отдельно от другого).
- **`reconcilePendingGateways(m)` (`reducer.js`):** группирует `pendingGateways` ВСЕХ проектов по `linkId`; ровно одна пара с противоположными `direction` ('out'+'in') — синтезирует живую `crossProjectLinks`-запись, убирает оба штекера. Вызывается после `ADD_PROJECT_FROM_FILE` (заполняет `pendingGateways` нового проекта из `data.externalGateways`) и после демоушена в `applyRemoveProject`. **Сверка только по `linkId`**, без проверки `remoteProjectId` — контрагент при повторном импорте получает свежий `projectId`, уцелевшая сторона помнит старый.
- **Новый экшен `UPDATE_PENDING_GATEWAY_PROXY`** (в однопроектном `reducer`, участвует в обычном Undo проекта) — Shift+драг штекера по рамке окна, аналог `UPDATE_PROXY_PORT`/`UPDATE_CROSS_PROJECT_PROXY_PORT`.
- **Визуализация:** `HierarchyUtils.getPendingGatewayProxiesForWindow` — новый прокси на рамке окна, грань/доля из самой записи (не пересчитываются). `LevelWindow.js` рисует только внутренний отрезок (без магистрали — рисовать нечего), маркер разрыва (полая точка) с тултипом «связано с «Порт» в проекте «Проект» (сейчас не загружен)», приглушённый пунктир вместо пульсации.
- **Тестирование:** +4 юнит-теста (`app/tests/projects.test.js`): примирение двух половин, одиночный штекер остаётся висеть, полный цикл `ADD_CROSS_PROJECT_LINK` → `REMOVE_PROJECT` (демоушен) → `ADD_PROJECT_FROM_FILE` (реимпорт с `externalGateways`, свежий `projectId`) → связь автоматически восстановлена, `getPendingGatewayProxiesForWindow`. Итого 240 юнит-тестов, 100% PASS; `tsc` — без новых ошибок. Живая проверка в браузере: полный цикл экспорт (смоделирован тем же кодом, что `handleExportProject`) → удаление проекта → штекер с корректным тултипом на холсте → повторный импорт → связь пересобралась и снова пульсирует, штекер исчез.

Три бага, найденные при обкатке готовой функциональности, и их исправления:

- **Баг 1 — выталкивание слоёв мешало вложить слой в слой при включённом Drag&Drop (`Layer.js`):** `suppressCollision` раньше зависел от асинхронного, троттленного по `requestAnimationFrame` резолвера цели (`lastTarget.valid`), тогда как выталкивание (`GeometryUtils.resolveLayerCollision`) применялось синхронно на каждое сырое движение мыши — слой «убегал» от собственной цели быстрее, чем резолвер успевал её подтвердить. Исправлено: подавление коллизии теперь безусловно зависит от одного флага `dragDropModeAtStart`, снятого один раз на `mousedown` — при включённом режиме выталкивание отключено всегда, независимо от того, есть ли валидная цель под курсором в данный момент.
- **Баг 2 (3a) — узел, назначенный на переносимый слой, пропадал из виду при пересечении границы окна уровня (`Canvas.js`):** переносимые элементы на время жеста рисуются отдельным оверлеем поверх всех окон (не обрезаемым их `overflow-hidden`), но в список id для этого оверлея попадал только сам перетаскиваемый слой — его parentId-вложенный узел оставался в обычном, обрезаемом рендере исходного окна и пропадал из виду ровно на время пересечения границы. Исправлено: список id для оверлея расширяется parentId-вложенными потомками (`HierarchyUtils.hasAncestorIn`), они едут в оверлее вместе со слоем.
  - Промежуточная попытка чинить это культингом `LevelWindow.js` (`alwaysKeep`, React-размонтирование по вьюпорту) оказалась не тем механизмом — визуальное исчезновение было CSS-обрезкой (`overflow-hidden`) внутри исходного окна, а не React unmount'ом — и была отменена (см. коммит-откат в этой же дате): без пользы, а на больших проектах (много слоёв/узлов, несколько открытых проектов) добавляла лишний полный проход по всем сущностям каждого проекта на каждое изменение выделения/жеста.

Выключен: перетаскивание клампится рамкой своего окна (единая дельта для группы — форма выделения не ломается), строки слоёв чужих уровней в поповерах «Назначить на слой» тусклые с подсказкой, кросс-уровневый сброс в дереве обозревателя отклоняется. Исключение, работающее всегда: группировка узлов в слои СВОЕГО уровня.
- **Резолвер целей `HierarchyUtils.getDropTarget`:** узлы и слои-приёмники — по ПЕРЕСЕЧЕНИЮ КОНТУРОВ с переносимым элементом, окна уровней — по указателю мыши; приоритет узел → слой → окно; из двух узлов побеждает тот, что под указателем, затем большее пересечение; переносимые и их потомки исключаются (защита от циклов); свёрнутые окна не принимают дроп; своё окно = обычное перемещение (isMove). Плюс `getLayerWorldBounds` / `getEntityWorldBounds`, `computeDropPositions` (мир → локаль целевого окна с камерой), `buildTransferConfirmText`.
- **Жест переноса (Node.js):** во время драга переносимые элементы рендерятся ПОВЕРХ всех окон той же отрисовкой (обёртка с transform вьюпорта в Canvas, pointer-events: none) — не прячутся под рамки; узел/слой-приёмник подсвечивается зелёным при пересечении контуров, окно — синей рамкой выделения (панель свойств уровня НЕ открывается); курсор not-allowed над пустотой и невалидными целями; Esc отменяет жест. Транзиентный стейт `dragGesture` (экшены `SET_DRAG_GESTURE` / `RESTORE_ENTITIES`, вне истории и сохранений).
- **Дроп с подтверждением:** отпускание на валидной цели показывает вопрос-предупреждение (`buildTransferConfirmText`: смена родителя/уровня, разрываемые связи, число элементов). «ОК» → `TRANSFER_NODE`: дроп на узел = вложение (`newOwnerId`; в том числе усыновление БЕЗ смены уровня — новая ветка sameLevel в редьюсере), дроп в слой = `targetLayerId` (авторасстановка), дроп на холст чужого окна = `targetLevelIndex` + `positionsById` (элементы ложатся под курсором, сохраняя раскладку группы, сиротами). «Отмена», пустота или невалидная цель — `RESTORE_ENTITIES` возвращает элементы на место без записи истории.
- **Один шаг Undo на весь жест:** `TRANSFER_NODE` принимает `historySnapshot` (срез на mousedown) — движение мышью и перенос откатываются вместе; `saveHistory` научился снапшот-оверрайду.

## 2026-08-23 — Щадящая очистка уровней, связь через поколение (ownerGap), удаление Главного холста

- **Очистка уровня больше не убивает потомков (`CLEAR_LEVEL_WINDOW`):** удаляются ТОЛЬКО сущности самого уровня. Выжившие потомки остаются на своих уровнях: осиротевший ребёнок пере-якоривается на ближайшего живого предка («внук — деду»), а без живых предков становится сиротой-якорем (`homeLevel`) со своей веткой. - **Связь через поколение — поле `ownerGap`:** дистанция до владельца в уровнях (нет поля — 1). Узел Главного холста может не иметь ребёнка на L1, но иметь «внука» на L2 — задел под будущий Drag&Drop между уровнями. `getLevel` суммирует дистанции по цепочке; `getOwnerGap` нормализует мусорные значения; «+» у брата узла со связью через поколение наследует дистанцию (`getAddContext.ownerGap` → Toolbar). Прямое назначение владельца (`TRANSFER_NODE`) дистанцию сбрасывает. Старые проекты читаются без миграции (аддитивное поле v11).
- **Удаление уровня учитывает дистанции (`REMOVE_LEVEL_WINDOW` / `applyRemoveLevelWindow`):** при пере-якорении «внук — деду» дистанции складываются минус снятый уровень; связи, перепрыгивавшие удаляемый уровень, сокращают `ownerGap` на 1 (внук становится обычным ребёнком после удаления пустого промежуточного уровня).
- **Удаление Главного холста — новый экшен `REMOVE_ROOT_CANVAS` и кнопка «Удалить холст»** в панели свойств L0: холст и его элементы удаляются, окно уровня 1 становится Главным холстом, НЕ меняя имя, цвет и камеру, потомки «ползут» на уровень вверх. Кнопка неактивна, когда других уровней нет (no-op в редьюсере); подтверждения нет намеренно — операция откатывается Undo, tooltip описывает последствия.
- **Полная очистка — новый экшен `CLEAR_PROJECT`:** кнопка «Очистить проект» переведена с каскадной очистки L0 на явный полный сброс содержимого всех уровней (окна, мастер-порты, камеры и настройки проекта сохраняются). Нужен потому, что очистка L0 теперь щадит потомков.
- **Ассистент:** системный промпт описывает новую семантику очистки/удаления, `ownerGap` и новые экшены; валидатор пропускает `REMOVE_ROOT_CANVAS` и `CLEAR_PROJECT`.

  - Полностью отключена автоматическая смена контекста при зумировании (`auto-dive`). Вход/выход из узлов теперь происходит строго по double-click или кнопкам навигации.
  - Удалена сложная концепция «затенённого хвоста» хлебных крошек (`breadcrumbTail`), мешавшая восприятию пути.
  - Убран навязчивый модал «Здесь пока пусто» из центра холста; вместо него добавлен лаконичный badge `Пусто (Esc — наверх)` прямо в строке хлебных крошек.
- **Отображение содержимого узлов:**
  - Отключен semantic zoom (`NodePreview`), скрывавший оригинальный текст и превью ноды при приближении. Теперь контент ноды (описание, картинки и т.д.) виден при любом масштабе.
  - Иконка слоёв на счётчике детей в правом верхнем углу нод заменена на `icon-boxes` для устранения путаницы с панелью слоёв.
- **Подсветка и иерархия связей (Z-Index & Pulsing):**
  - Реализована плавная пульсация родительских узлов (`animate-parent-pulse`) их собственным цветом (`node.color`) при выборе любого вложенного узла. Эффект использует динамические цвета через CSS-функцию `color-mix` и не вызывает мерцания текста.
  - Исправлен баг Z-index, из-за которого родительские узлы при выборе дочернего перекрывали дочерний узел. Внедрён строгий расчёт z-index на основе глубины вложенности (`depth * 10`), что гарантирует корректный рендер вложенных элементов поверх их контейнеров.
  - Включено сквозное взаимодействие (выбор, перемещение, клик) с X-Ray объектами родительских/соседних уровней (добавлен `pointer-events-auto` для X-Ray узлов и исправлено перекрытие родителями).
  - Разрешено перетаскивание активного контейнера (контекстного узла, внутри которого находимся) — теперь он перемещается вместе со всеми своими дочерними элементами.
- **Инструменты и очистка:**
  - Исправлена кнопка «Очистить проект» в тулбаре: теперь она корректно удаляет текущее состояние `architector_state_v10` из localStorage.
  - Вырезаны невостребованные боковые панели сквозных связей (`TunnelLabels`) и панель среза высот (`DepthProfile`) для разгрузки рабочей области.
  - Полностью удалена функция вложения перетаскиванием (`drag-to-nest`) на холсте во избежание случайного перевложения при обычном перемещении узлов. Перевложение теперь производится строго и безопасно через вкладку «Дерево» в левой библиотеке.
