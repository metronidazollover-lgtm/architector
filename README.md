# Architector — Visual Logic Node Editor

**Architector** — это интерактивный визуальный редактор иерархических графов (нодовых диаграмм), предназначенный для проектирования логики приложений, диаграмм потоков данных и архитектурных схем (например, цепочек промптов и интеграции ИИ-ассистентов).

Ключевая парадигма (v11): **пространственные окна уровней**. Каждый уровень иерархии — Главный холст (L0), Уровень 1, Уровень 2 и глубже — представлен отдельным перемещаемым окном (`LevelWindow`) на общем бесконечном мировом холсте. Родство узлов между уровнями выражается полем `ownerId` («владелец»), а координаты каждого узла локальны холсту его уровня.

## 🚀 Технологический стек
Проект выполнен по схеме "zero-build" и работает полностью в браузере без необходимости предварительной сборки:
* **Core:** React 18 & ReactDOM 18 (загружаются через CDN).
* **Компиляция JSX:** Babel Standalone (транспиляция кода на лету в браузере).
* **Стилизация:** Tailwind CSS (Play CDN с поддержкой кастомных стилей и директив `@layer`).
* **Иконки:** Lucide Icons (статический шрифт).
* **Сервер:** Локальный веб-сервер на Python (`server.py`, с заголовками no-cache — иначе браузер кэширует text/babel-скрипты и после правок исполняет смесь старых и новых файлов). Дополнительно все скрипты в `index.html` подключаются с меткой версии (`?v=...`): после правок компонентов метку следует поднимать, чтобы гарантированно сбросить кэш и у пользователей, открывающих страницу без dev-сервера.

## 📂 Структура проекта

* `app/index.html` — главная точка входа. Подключает стили Tailwind, Google Fonts (11 гарнитур), библиотеки и скрипты компонентов типа `type="text/babel"`. Новые компоненты добавляются сюда отдельной строкой script (порядок: utils → store → компоненты → app).
* `app/app.js` — корневой компонент приложения с предохранителем `ErrorBoundary` и рендером в DOM.
* `app/run.bat` — скрипт автозапуска. Запускает `server.py` на порту 3000 и открывает страницу приложения в браузере по умолчанию.
* `app/server.py` — сервер разработки с запретом кэширования.
* `app/store/reducer.js` — чистая логика состояния: defaultState, редьюсер, миграции формата (v9 → v10 → v11), нормализация окон уровней, загрузка из localStorage. Без JSX, исполняется и в Node (тесты). ВАЖНО: редьюсер не должен вызывать сам себя — общая логика выносится в top-level функции (например, `applyRemoveLevelWindow`), иначе babel-standalone перестаёт публиковать `const reducer` для остальных скриптов.
* `app/store/Store.js` — React-провайдер поверх редьюсера (`useReducer` + `Context API`). Поддерживает:
  * Сохранение состояния в `localStorage` (ключ `architector_state_v11`; legacy-ключи `architector_state_v10` / `architector_state_v9` конвертируются при первом запуске, см. `docs/MIGRATIONS.md`), дебаунс 400 мс + синхронный флаш при закрытии вкладки.
  * Историю действий (Undo/Redo на 20 шагов).
  * Операции с буфером обмена (Copy/Paste узлов).
  * Массовые операции (`MASS_UPDATE`, `DELETE_SELECTED`).
* `app/utils/hierarchy.js` — иерархия и координатное ядро уровней:
  * `getLevel` / `getEntityLevel` — уровень сущности по цепочке владения (`ownerId`) с учётом слоёв-контейнеров, легаси-родства и связи через поколение (`ownerGap`: владелец может жить на 2+ уровня выше — дистанции по цепочке складываются). `getOwnerGap` — нормализация дистанции (нет поля / мусор → 1).
  * `getLocalPosition`, `getWorldTransform`, `getPortWorldPosition`, `getNodeWorldBounds` — переводы координат «локальные ↔ мировые» с учётом камер окон.
  * `getWindowOfLevel`, `getLevelView` (камера окна: `innerOffset`, `innerZoom`, `isCollapsed` в `state.levelViews`), `LEVEL_WINDOW_METRICS`.
  * `getProxyPortsForWindow` — прокси-порты межуровневых связей на рамках окон (авторасстановка + ручные позиции `link.proxyOverrides`).
  * Изоляция веток («глаз»): `toFocusList`, `getBranchOwner`, `hasAncestorIn`, `isEntityVisible` — единая точка истины видимости (глобальный глаз Главного холста приоритетен и просвечивает ветки выделенных корней на всех уровнях; локальные глаза действуют в пределах своего уровня).
  * `getAddContext` — контекст создания узла/слоя кнопкой «+» (брат выделенного по `ownerId`, с наследованием дистанции `ownerGap` у братьев «через поколение»; сирота-якорь на кликнутом уровне, если фокусной ветки нет; `ok:false` при массовом выделении или неоднозначной ветке).
  * `canTransferToLayer` — вердикт переноса узла в слой (группировка / усыновление / «спуск» в собственную ветку) для UI-подсказок и валидации.
  * Drag & Drop: `getDropTarget` — резолвер цели жеста (узлы/слои по пересечению контуров, окна по указателю, приоритет узел → слой → окно, потомки исключаются, свёрнутые окна не принимают дроп, dnd-off при выключенном тумблере); `getLayerWorldBounds` / `getEntityWorldBounds`; `computeDropPositions` — мировые координаты → локаль целевого окна с учётом камеры; `buildTransferConfirmText` — текст вопроса-подтверждения перед переносом.
* `app/utils/geometry.js` — математический модуль для расчета геометрии графа:
  * `getPortRelativePosition` — расчет точных координат портов на гранях узлов.
  * `buildLinkPath` — построение путей связей (Bezier / Orthogonal), единое для внутриуровневых и межуровневых сегментов.
  * `getSmartPlacement` — алгоритм автоматической раскладки узлов внутри слоя без перекрытий с динамической оптимизацией размера слоя под его контент (fit-to-content).
  * `resolveLayerCollision` — алгоритм разрешения коллизий (выталкивания) слоёв при перетаскивании, предотвращающий их наложение друг на друга.
* `app/components/` — React-компоненты интерфейса:
  * `Canvas.js` — общий (мировой) холст: панорамирование, зум колесом (Ctrl/Cmd+колесо — зум мирового холста из любой точки, в том числе над окнами уровней), рендер окон уровней, глобальный SVG-слой межуровневых пунктирных связей (скрытые изоляцией концы не рисуются), хоткеи (Delete удаляет и выделенное окно уровня, кроме Главного холста).
  * `LevelWindow.js` — пространственное окно уровня: шапка с drag-перемещением, мастер-порт, кнопки «глаз»/свернуть/крестик (у L0 крестик очищает — дети L1 становятся сиротами со своими ветками; у остальных удаляет уровень), внутренний вьюпорт с собственной камерой (колесо — зум окна; подписка через callback-ref, переживающий сворачивание/разворачивание), прокси-порты межуровневых связей на рамке (Shift+драг двигает их по периметру), фильтрация содержимого через `isEntityVisible`.
  * `Node.js` — визуальное представление узла: авторесайз, панель действий, кнопка `+`/бейдж `📁 N` для вложенных узлов; клик без сдвига схлопывает массовое выделение до узла (драг группы за выделенный узел сохранён).
  * `Layer.js` — контейнер-слой. Позволяет визуально группировать узлы и перемещать их совместно. Предотвращает перекрытие с соседними слоями за счет скольжения по границам при перетаскивании. **Полноправный участник графа связей наравне с узлом**: несёт порты на всех 4 гранях (клик по грани в режиме `add-port`, Shift+драг скользит порт по периметру), может соединяться связями со слоями и узлами (Слой ↔ Слой, Слой ↔ Узел).
  * `Port.js` — точка подключения связей на границе узла ИЛИ слоя (хост-сущность разрешается полиморфно: `nodes[id] || layers[id]`) (Shift+драг — скольжение порта по периметру; перетаскивание от порта — создание связи, при сбросе в окно другого уровня узел/слой-приёмник наследует фокус-владельца ветки этого уровня).
  * `Link.js` — соединительная линия между портами узлов и/или слоёв (кривые Безье и ортогональные линии, подсветка сети).
  * `NodePreview.js` — семантическое превью геометрии и контента ноды при изменении масштаба.
  * `ContextActionBar.js` — контекстная панель свойств в едином визуальном стиле для всех типов (проект, уровень, узел, слой, порт, связь, массовое выделение): позиция `top-4`, ширина 794px, тёмный фон; бейдж типа фиксированной ширины 110px, окрашиваемый в цвет элемента (по умолчанию `#191c23`); во всех цветовых поповерах — пресеты, «Свой цвет» и пипетка (EyeDropper API, Chrome/Edge); у уровня — кнопки «Очистить» (все уровни; удаляются только сущности самого уровня, потомки выживают: «внук — деду» через `ownerGap` или сирота-якорь) и «Удалить» (для L≥1 — уровни ниже поднимаются; для L0 — кнопка «Удалить холст», `REMOVE_ROOT_CANVAS`: Уровень 1 становится Главным холстом с прежним именем и цветом; неактивна без других уровней, подтверждения нет — есть Undo). Кнопка «Очистить проект» в панели проекта — полный сброс содержимого всех уровней (`CLEAR_PROJECT`). Поповер «Назначить на слой» показывает слои всех уровней: чужой уровень помечен бейджем `L№` и работает через `TRANSFER_NODE`, слой собственной ветки — «↓ ветка» (спуск), пункты, рвущие родственные связи, обведены красной рамкой с предупреждающим tooltip. Поле «Группа» удалено из UI (легаси).
  * `Toolbar.js` — левая панель управления (добавление узлов/слоев по `getAddContext` — кнопки гаснут с подсказкой при неоднозначной цели; без фокусной ветки «+» создаёт сироту-якоря на активном уровне; выравнивание слоев, экспорт/импорт JSON, изоляция выделенного, загрузка демо-проекта, вызов AI-ассистента).
  * `Library.js` + `OutlinerTree.js` — панель-обозреватель проекта шириной 350px (вкладки: Объекты и История); вкладка «Узлы» группирует узлы по СЛОЯМ (заголовок-слой выделяет все его узлы), дерево принимает сброс узла на слой другого уровня как перенос (`TRANSFER_NODE`).
  * `AIAgentNodeContent.js` — интерфейс встроенного ИИ-ассистента для узлов типа `ai-agent` с возможностью автоматического изменения графа на основе JSON-команд.

* `app/types/` (`typedefs.js`, `globals.d.ts`) + `app/jsconfig.json` — JSDoc-типы и глобальные декларации TypeScript; проверка: `npx -y -p typescript tsc -p app/jsconfig.json`.
* `app/tests/` — юнит-тесты чистой логики; запуск: `node --test app/tests/*.test.js`. Точное число тестов намеренно не дублируется в документации: единственный источник правды — вывод самого прогона.
* `app/bench/` — измерительная оснастка: `core.bench.js` (чистая логика на сценах S/M/L), `render.bench.js` (перерисовки и FPS в headless-браузере), `syntax-check.js` (разбор всех JSX-файлов до открытия страницы), `offline-harness.js` (стенд с локальными копиями CDN-библиотек). Результаты — в `docs/BENCHMARKS.md`.

## 🗂️ Мультипроектность (v12)

Состояние верхнего уровня — набор проектов: `{ projects, projectOrder, activeProjectId, projectCounter }`. Каждый проект хранит собственные сущности, окна уровней, камеры и **собственную историю Undo**; камера общего холста, настройки интерфейса и выделение — глобальные. Панели (`Toolbar.js`, `Library.js`, `ContextActionBar.js`) и узел ИИ-ассистента (`AIAgentNodeContent.js`) по-прежнему читают плоский вид АКТИВНОГО проекта (`mergeActiveView` через `useStore()`/`useSelector()`) — для них ничего не изменилось.

Окна всех проектов живут на одном мировом холсте колонками. **С PLAN V6 неактивные проекты полностью интерактивны наравне с активным**: узлы, слои, порты и связи чужого (неактивного) проекта кликабельны, выделяемы, перетаскиваемы и редактируются на месте — компоненты холста (`Node.js`, `Port.js`, `Layer.js`, `Link.js`) читают и пишут СВОЙ проект напрямую через `ProjectContext`/`getProjectFlatView`, минуя активный проект (см. раздел «Как компоненты получают состояние» ниже). Клик по элементу неактивного проекта мягко делает его активным для верхних панелей (свойства, Undo-тулбар), не прерывая жест. Межпроектные связи и перетаскивание узлов между проектами при этом намеренно заблокированы защитными барьерами (см. `PLAN_V7_CROSS_PROJECT_INTERACTIONS_AND_IO.md`) — это следующий этап. Ключ хранилища — `architector_state_v12`; подробности перехода — в `docs/MIGRATIONS.md`.

**Проекты и уровни можно выделять пачками** (Shift+клик по плашке проекта или шапке окна), изолировать на холсте, оформлять, выравнивать и удалять — см. `docs/UX.md`.

> **История Undo не переживает перезагрузку страницы.** В пределах вкладки она работает полностью, но в хранилище снимки не пишутся: 20 снимков сущностей на проект переполняли квоту браузера на крупных проектах.

## ⚙️ Как компоненты получают состояние

Состояние живёт вне React — в движке `app/store/engine.js`; компоненты подписываются на него через `useSyncExternalStore`. Хук `useStore()` отдаёт полный плоский вид АКТИВНОГО проекта (прежний контракт, `mergeActiveView`), `useSelector(selector)` — точечную подписку на него же.

**Компоненты холста (Node/Port/Layer/Link) на это не полагаются.** У них есть свой проектный слой поверх того же движка (`Store.js`):
* `ProjectContext` — React-контекст, несущий `projectId` конкретного окна проекта на холсте (`null` = активный проект по умолчанию). Каждый `LevelWindow` и Drag-оверлей на холсте обёрнут в `<ProjectContext.Provider value={projectId}>` (`Canvas.js`).
* `getProjectFlatView(projectId)` — гранулярный кэш плоского вида ЛЮБОГО проекта (не только активного): инвалидируется по ссылке на `state.projects[projectId]`, а не по общему корню состояния, поэтому движение мыши и экшены в чужих проектах не сбрасывают его и не вызывают лишних перерисовок.
* `useProjectSelector(selector)` / `useProjectDispatch()` — читают `projectId` из `ProjectContext` и работают со своим проектом: чтение идёт через `getProjectFlatView(projectId)`, а `dispatch` для неактивного проекта автоматически заворачивает экшен в `{ type: 'FOR_PROJECT', payload: { projectId, action } }`, не трогая активный проект.

Панели (`Toolbar.js`, `Library.js`, `ContextActionBar.js`) используют обычные `useStore()`/`useSelector()`/`useDispatch()` и работают с АКТИВНЫМ проектом — осознанное решение для верхних панелей. Узел ИИ-ассистента (`AIAgentNodeContent.js`) — отдельный случай: он рендерится внутри `NodeView` конкретного проекта на холсте, поэтому читает и пишет `useProjectStore()` (2026-08-29) — аналог `useStore()`, но привязанный к `ProjectContext`, как у `Node.js`/`Port.js`/`Layer.js`/`Link.js`. До этой правки узел-ассистент в неактивном проекте молча читал и менял активный проект — баг того же семейства, что чинили для окон уровней.

Важное правило для новых компонентов: селектор считает производные значения (мировая позиция, уровень, видимость, флаги подсветки) и сравнивается по РЕЗУЛЬТАТУ, а не подписывается на «свою запись» в состоянии. Иначе теряется «рябь» — изменение далёкого предка, которое обязано дойти до потомка. Инвариант закреплён тестами `app/tests/reactivity.test.js`.

### Детали полей:
* **Окна уровней (`levelWindows`):** словарь по стабильному `id` окна (окно Главного холста — `lvlwin-root`). Номер уровня — поле `levelIndex`; при удалении уровня нижележащие окна сохраняют id и рамку (имя, цвет, позицию, размер), меняется только их `levelIndex`.
* **Камеры окон (`levelViews`):** панорама (`innerOffset`), зум (`innerZoom`) и свёрнутость (`isCollapsed`) каждого окна; ключ — id окна. Живут вне снапшотов истории: Undo структурных правок не дёргает точку обзора.
* **Система координат (v11):** `position` узла/слоя локальна холсту его уровня. `parentId` — координатный контейнер («где лежит»): `"root"` = холст уровня, либо id слоя-контейнера. Родство между уровнями выражается `ownerId`: уровень сущности равен длине цепочки владения (`HierarchyUtils.getEntityLevel`).
* **Версия формата (`formatVersion`):** текущая — `11`. Файлы v10 (относительные координаты от родителя) и v9 (мировые координаты) конвертируются при импорте автоматически. Детали: `docs/MIGRATIONS.md`.
* **Изоляция веток («глаз»):** `levelHideNeighbors` — включённость глаза по уровням (ключ — номер уровня; уровень 0 — глобальный глаз, приоритетный над локальными); `levelFocusParentId` — фокус-наборы веток по уровням (массивы id владельцев; легаси-строка читается как набор из одного).
* **Сироты-якоря (`homeLevel`):** необязательное поле узлов и слоёв; сущность без `ownerId` с `homeLevel: N` живёт на уровне N как глава независимой ветки (её дети — на N+1). Поля нет — уровень 0 (прежнее поведение). Поле `group` узлов — легаси, интерфейсом не используется.
* **Связь через поколение (`ownerGap`):** необязательное поле узлов и слоёв; дистанция до владельца в уровнях (нет поля — 1, обычное родство). Появляется при очистке промежуточного уровня: выжившие потомки пере-якорятся на ближайшего живого предка («внук — деду») и остаются на своих уровнях. `getLevel` суммирует дистанции по цепочке; прямое назначение владельца (`TRANSFER_NODE`) сбрасывает дистанцию; удаление уровня, который связь перепрыгивала, сокращает её на 1. Старые проекты читаются без миграции.
* **Ручные позиции прокси-портов (`links[].proxyOverrides`):** словарь `{ [windowId]: { edge, fraction } }` — положение прокси-порта межуровневой связи на рамке окна (задаётся Shift+драгом). Прокси без записи авторасставляются по граням.
* **Мастер-порты уровней:** порты с id `port-master-level-N` (`isMaster: true`, `windowIndex: N`) принадлежат окнам уровней, а не узлам; при сдвиге уровней перенумеровываются вместе со ссылками из связей.
* **Грани портов (`edge`):** `left`, `right`, `top`, `bottom`; `position` — смещение вдоль грани (0.0–1.0).
* **Типы узлов (`type`):** `'default'` или `'ai-agent'` (интерактивная панель чата с ИИ-ассистентом).
* **Изоляция с тулбара (`isolatedIds`):** массив ID элементов, оставленных видимыми в режиме изоляции. Пустой массив — изоляция выключена.
* **Режим Drag&Drop (`ui.dragDropMode`):** тумблер в панели свойств проекта. Включён — жестом доступны межуровневые переносы и вложения (дроп на узел = стать его ребёнком; дроп в слой = положить в слой с авторасстановкой; дроп на холст чужого окна = сирота на том уровне, элементы ложатся под курсором) — каждый перенос предваряется вопросом-подтверждением, весь жест откатывается одним Undo. Выключен (дефолт при каждой загрузке) — элементы не пересекают границы своих окон (клампинг), доступна только группировка в слои своего уровня; кросс-уровневые строки поповеров тусклые с подсказкой. Транзиентный стейт жеста — `state.dragGesture` (вне истории и сохранений).
